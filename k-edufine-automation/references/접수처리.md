## 7단계: 본문·첨부 PC저장

접수 공문 원본을 파일로 받아 두는 작업. **창이 4겹**으로 이어진다.

```
HCLTAPP_KYUL_ (#32770, MSHTML)          ← 결재 문서 창
  └ "파일저장 | 업무관리시스템 -- 웹 페이지 대화 상자"   (TridentDlgFrame, MSHTML)
      └ "문서저장 -- 웹 페이지 대화 상자"                (TridentDlgFrame, MSHTML)
          └ "폴더 찾아보기"                             (#32770, Win32 — MSHTML 아님)
```

앞의 셋은 `mshtml_dom.ps1` 로 제어된다. 마지막 "폴더 찾아보기"는 경로 편집란이 `WS_DISABLED`
라 자동 입력이 안 되므로 **취소하고, 문서저장 모달의 저장 함수 소스에 경로를 박아 넣는다**
(아래 여섯 걸음).

**호출 사슬 (읽어서 확인한 것)**

- 우상단 아이콘 `fncSavePC()` → `docSave('doccrdMain')`
- `docSave` 분기
  - `rInfo.draftsrc == '4'` (비전자접수문서): 첨부 동반 여부를 confirm 으로 물음
  - **`applId == '5010'` (접수대기 문서)**: `alert("열람권한이 없습니다.\n접수처리 후
    저장하시기 바랍니다.")` 후 return. **접수처리 전에는 저장 자체가 막힌다.**
    저장 실패 시 이 분기부터 의심할 것 (정상 결재대기 문서는 `applId 2010`)
  - 그 외: 모달 팝업 `retrieveDocListBdtStre.do` 로 넘김
- 파일저장 대화상자 → `fncVerify()` → `bdtStreAt=='Y'` 면 `fncMultiVerify()`
- 문서저장 모달의 **`init()`** (약 23KB)이 실제 저장을 수행

**파일저장 대화상자 옵션 id**

| id | 뜻 | 기본 |
|----|----|------|
| `hwpsave` / `attsave` / `sisave` / `hoxsave` | 본문 / 첨부파일 / 시행문 / 문서정보 | 앞 둘만 체크 |
| `HWPDISTSAVE01` / `HWPDISTSAVE02` | 비배포(ODT) / 배포(PDF) | 01 |
| `CHOSAVE03` / `CHOSAVE02` / `CHOSAVE04` | 파일명 규칙 3종 | 03 |

**저장 절차: 여섯 걸음**

시작 전에 결재 창에서 `applId`(위 `5010` 분기)와 첨부 건수
`D$('HSAttach1').getFilesCount()` 를 확인한다. 첨부가 0 이면 `HSFileBox` 의 `tbody` 도 비어
있고 OBJECT 의 `AttachCount` 파라미터도 0 이다. "첨부도 받아 달라"는 요청에는 0건임을 근거와
함께 보고한다.

1. 결재 창(`kyul_dom.ps1`)에 `fncSavePC()` 를 `setTimeout` 으로 주입 → 파일저장 대화상자가 뜬다
2. 파일저장 대화상자(`mshtml_dom.ps1 -TitleLike "파일저장"`)에서 옵션을 확인한다(본문·첨부 체크,
   `HWPDISTSAVE01`)
3. 같은 대화상자에 `fncVerify()` 를 `setTimeout` 으로 주입 → **문서저장 모달과 "폴더 찾아보기"가
   한꺼번에** 뜬다(패치를 넣을 틈은 없다)
4. `dlg.ps1 -TitleLike "폴더 찾아보기" -Click 2` 로 **취소**한다(`WM_COMMAND`/IDCANCEL,
   `CLICKED id=2` 출력으로 검증). 문서저장 모달은 그대로 살아 있고 `pMsg` 가
   `저장을 취소하였습니다.` 가 된다
5. 문서저장 모달(`mshtml_dom.ps1 -TitleLike "문서저장"`)에 아래 [1차] 패치를 주입하고 `PATCH ok` 를 확인한다
6. [2차] 실행을 주입하고 `pMsg.innerHTML` 로 결과를 확인한 뒤, PowerShell 로 최종 위치에 옮기고
   `fncClose()` 를 문서저장 → 파일저장 순으로 주입해 정리한다(앞의 것만 닫아도 대개 함께 닫힌다)

**경로 패치**

문서저장 모달의 `init()` 안에서 `FileManager.selectFolderEx(...)` 호출부만 경로 리터럴로 바꿔
재정의한다. ActiveX 객체(`FileManager`)에 메서드를 덮어쓰는 것은 실패하므로 **함수 소스 치환**이 답이다.
경로의 백슬래시는 `String.fromCharCode(92)` 로 조립한다(SKILL.md 6단계 주입 JS 규칙).

**패치와 실행은 두 번에 나눠 호출한다.** 한 덩어리로 보내면 패치 실패가 "출력 없음" 으로만
보인다. 1차로 패치 결과를 확인하고, 2차로 실행한다.

**저장 경로는 ASCII 임시 폴더로 받고 PowerShell 로 최종 위치에 옮긴다.** 한글·공백이 섞인
클라우드 드라이브 경로를 ActiveX `CopyFile` 에 직접 주는 위험을 피한다. 먼저 PowerShell 로
`New-Item -ItemType Directory -Force "$env:TEMP\kedu1"` 를 만들고, 그 전체 경로
(`$env:TEMP\kedu1` 을 펼친 값)를 `/` 구분자로 바꿔 아래 `DIR` 한 줄에 넣는다. 펼친 경로에 한글·공백이
섞인 PC라면 쓸 ASCII 임시 경로를 사용자에게 묻는다.

```javascript
// [1차] 문서저장 모달에 주입 — 패치만 하고 결과를 회수한다
(function () {
  try {
    var DIR = "C:/Users/<사용자>/AppData/Local/Temp/kedu1";  // ← $env:TEMP\kedu1 을 / 로 바꿔 넣는다
    var src = init.toString();
    var re = /FileManager\.selectFolderEx\([^)]*\)/;      // 호출은 정확히 1곳
    if (!re.test(src)) { window.__r = "NO MATCH"; return; }
    var P = String.fromCharCode(92);                       // ← 백슬래시
    var path = '"' + DIR.split("/").join(P + P) + '"';
    var patched = src.replace(re, path);
    window.__patchedInit = eval("(" + patched + ")");
    try { document.getElementById("pMsg").innerHTML = ""; } catch (e) {}
    window.__r = "PATCH ok; type=" + (typeof window.__patchedInit);
  } catch (err) { window.__r = "ERR " + err.message; }     // ← 없으면 무증상 실패
})();
```

```javascript
// [2차] PATCH ok 를 확인한 뒤에만 실행
window.__r = "scheduled";
setTimeout(function () { try { window.__patchedInit(); } catch (e) { } }, 300);
```

- `init()` 은 인자가 없고 전역 `obj`(USERID·APPRIDLIST·fileGbn·saveChoice·hwpChoice 등)와
  `pMsg` 를 쓴다. eval 로 만든 사본도 전역 스코프라 그대로 동작한다.
- 결과 확인은 `pMsg.innerHTML` — 저장된 전체 경로와 `...... ok`, 끝에
  "결재문서들을 모두 저장하였습니다." 가 찍힌다.
- "폴더 찾아보기" 경로 편집란에 `WM_SETTEXT`·`BFFM_SETSELECTION` 등으로 경로를 넣으려 하지 않는다
  (편집란은 `WS_DISABLED`, `WM_USER` 계열 메시지는 앱을 죽인다 → 기술노트.md).

**본문은 기본값(비배포 ODT)으로 받는다 — ODT 는 텍스트가 살아 있다.**
`HWPDISTSAVE01`(비배포) 기본값으로 저장한 `.odt` 는 `content.xml` 에서 본문이 그대로
추출된다. 접수 공문 내용을 읽어 요약·후속 처리하는 것이 목적이면 굳이 배포(PDF)로
바꾸지 말 것.

```python
import zipfile, re, io
z = zipfile.ZipFile(ODT); x = z.read('content.xml').decode('utf-8')
x = re.sub(r'</text:p>', '\n', x)      # 문단 경계 보존(태그 제거 전에)
x = re.sub(r'<[^>]+>', '', x)
io.open('out.txt', 'w', encoding='utf-8').write(x.strip())
```

**추출 결과를 터미널로 흘리면 한글이 깨진다.** 콘솔 코드페이지 때문에 `print` 출력이
`�߰���ü����` 처럼 보여 "추출 실패" 로 오판하게 된다. **UTF-8 파일로 쓴 뒤
`cat`/Read 로 읽을 것.** (나이스 스킬의 `pdftotext -enc UTF-8` 함정과 같은 계열)

**반면 배포(PDF)로 저장한 것은 텍스트가 안 뽑힌다**: 글꼴에 유니코드 매핑이 없어 추출
결과가 깨진다(스크린 리더로도 못 읽는다). PDF 로만 받았다면 **렌더링해서 읽고 텍스트본을
따로 만들어 함께 저장**한다.

```bash
python -c "import fitz; d=fitz.open(PDF); d[0].get_pixmap(dpi=170).save('p1.png')"
# → 이미지로 읽어 .txt 로 옮겨 적고, 임시 PNG 는 삭제
```

### 8-3. 지정 결과는 INPUT 이 아니라 HOX XML 에 들어간다

```javascript
get_text(domHox1, '/hox/docInfo/taskInfo/taskCard/cardID');    // 실제 저장 위치
get_text(domHox1, '/hox/docInfo/taskInfo/taskCard/cardName');
```

**`untkID`·`mngtkID` hidden 은 빈 채로 남는다.** 이 값만 보고 "과제카드가 안 붙었다"고
판단하면 오판이다. 화면 표시는 `#dvTkcrdEdit` 행의 `#taskInfo` span.

**검증은 `cardID` 존재가 아니라 `cardName` 문자열로 한다.** XML 구간을 통째로 떠서
눈으로 확인하는 쪽이 정규식 한 줄보다 안전하다. `cardID` 만 정규식으로 뽑아
"있으면 지정됨" 으로 판정하면, 미지정 상태에서 빈 캡처(`<cardID></cardID>` 또는 매치
실패 시 기본값)를 참으로 읽어 **지정 안 된 문서를 지정됐다고 보고**하게 된다. → 사례

```javascript
(function () {
  try {
    var x = domHox1.xml, i = x.indexOf("taskCard");
    window.__r = (i >= 0 ? x.substring(i - 20, i + 300).replace(/\s+/g, " ") : "(not found)")
               + "\nuntkID=[" + document.getElementById('untkID').value + "]"
               + "\n화면=" + document.getElementById('dvTkcrdEdit').innerText.replace(/\s+/g, " ");
  } catch (err) { window.__r = "ERR " + err.message; }
})();
```

지정 전에는 `taskCard` 자체가 없고(`(not found)`) 화면 span 도 `* 과제카드` 뿐이다.
지정 후에는 `<cardName>[선별적교육비지원] 교육급여및교육비지원</cardName>` 처럼 이름이
찍히고 화면에도 `(5년)` 보존기간까지 붙는다. **이 두 상태를 눈으로 비교하고 넘어간다.**

### 8-4. 보안·공개 확인

결재정보 탭의 `othbcLmtt1/2/3`(공개·부분공개·비공개)이 원 문서 값으로 이미 설정돼 있다.
**공개 문서면 공개제한근거 `othbcAt1~8`(1~8호)은 전부 `disabled`** — 체크할 수 없고
할 필요도 없다. 비공개·부분공개일 때만 활성화된다. 기존 설정은 그대로 두는 것이 기본이다.

### 8-5. 문서처리

`fncProcessDoc()`(`setTimeout`) → "문서처리 | 업무관리시스템 -- 웹 페이지 대화 상자"(MSHTML 대화상자).

- 이 대화상자에도 대국민공개여부·관계법령 1~8호·공개제한기간·게시판 필드가 **존재하지만
  평소에는 숨겨져 있다**(`offsetParent === null`). 공문게시를 지정할 때만 노출된다.
  `checked=false` 만 보고 "체크가 빠졌다"고 오판하지 말고 **`offsetParent` 로 노출 여부를
  먼저 확인**할 것.
- 실제로 보이는 것은 처리구분(`docprocess` 가 기본 선택됨)·의견작성·의견첨부뿐이다.
- 확인 = `fncVerify()` (앵커 `#aSubmit`).

### 8-6. Win32 메시지 창 처리

`fncVerify()` 뒤에 클래스 `#32770`, 제목 **"웹 페이지 메시지"** 창이 뜬다. MSHTML 대화상자가
아니라 Win32 메시지 창이다. 기안(10-9·10-10)과 공개구분 수정(10-13)에서 뜨는 창도 같은 규칙을 따른다.

- 문구는 자식 `Static`(보통 `id=65535`)에서 읽는다.
- **버튼 컨트롤 ID 가 창마다 다르다.** 넘겨짚지 말고 매번 `dlg.ps1 -TitleLike "웹 페이지 메시지"`
  로 컨트롤을 덤프해 확인한 뒤 `-Click <id>` 로 누른다(`PostMessage(hwnd, WM_COMMAND, id, 0)`).
- **`dlg.ps1` 의 버튼 클릭 파라미터는 `-Click` 이다** (`-ClickId` 아님). 이름을 틀리면
  PowerShell 이 오류 없이 **덤프만 하고 끝나서** 클릭한 줄 알고 넘어가게 된다.
  출력 끝에 `CLICKED id=N` 이 찍혔는지 확인할 것.

관찰된 버튼 id(참고용. 누르기 전에는 매번 덤프한다):

| 창 | 문구 | 확인 | 취소 |
|---|---|---|---|
| 문서처리 confirm (8-5) | "문서를 결재하시겠습니까 ?" | 1 | 2 |
| 문서처리 결과 alert (8-5) | "정상적으로 처리되었습니다." | 2 | |
| 임시저장 결과 alert (10-9) | "정상적으로 처리되었습니다." | 2 | |
| 내부결재 confirm (10-10) | "수신자를 지정하지 않으면 내부결재로 처리됩니다. 계속하시겠습니까?" | 1 | 2 |
| 결재올림 결과 alert (10-10) | "정상적으로 처리되었습니다. / 결재완료후 …" | 2 | |
| 공개구분 수정 결과 alert (10-13) | "정상적으로 저장되었습니다." | 2 | |
| 직원열람제한 안내 alert (10-13, 부분공개 클릭 때) | 안내 문구 | 2 | |

처리가 끝나면 **결재 창(WXSClient)이 스스로 닫힌다.** 창이 사라진 것은 정상 완료 신호다.
