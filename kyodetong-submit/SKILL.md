# 교데통 데이터취합 제출 가이드

## 개요

교데통은 K-에듀파인 '자료집계'를 대체하는 교육데이터통합플랫폼이다. 교육청·학교 간 데이터 취합 업무를 처리한다.

> **적용 범위**: 서울특별시교육청 환경(`sen.edmgr.kr`)에서 실사용으로 검증했다. 교데통은 전국 공통
> 플랫폼이며 시도별 서브도메인(각 시도 업무포털 SSO)만 다르다.

> **표기**: 본문에 **〔매뉴얼〕**이 붙은 항목은 공식 사용자매뉴얼(2025.11.) 기준이고 아직 실사용으로 확인하지
> 않았다. 표시가 없는 내용은 실제 제출에서 확인한 것이다. 화면 문구가 매뉴얼과 어긋나면 **실측을 따른다**
> (매뉴얼은 탭을 `접수대기`, 제출방법을 `바로취합`으로 적고 `공문시행`이 남아 있는 등 현재 화면과 다르다).

이 문서는 **제출자**(자료를 내는 쪽) 절차만 다룬다. 요청자(취합을 거는 쪽)의 요청자료 등록·서식 생성·마감은
교육청 담당자 업무라 범위 밖이다.

## 접속 경로 (중요 — 도메인이 두 개다)

| 도메인 | 정체 | 로그인 |
|--------|------|--------|
| `www.edmgr.kr` | **공개 교육데이터플랫폼** (데이터찾기·개방·활용) | 일반 회원가입 / 네이버 / 카카오 |
| `sen.edmgr.kr` | **업무용 교데통** (데이터취합) — 시도 서브도메인 | 업무포털 SSO |

**데이터취합은 `sen.edmgr.kr`에만 있다.** 공개 포털에는 데이터취합 메뉴 자체가 없고 로그인 수단도 다르므로, `www.edmgr.kr`로 들어가면 아무리 뒤져도 제출 화면을 찾을 수 없다.

진입 절차:

1. 업무포털 `https://sen.eduptl.kr/bpm_man_mn00_001.do` → 미로그인이면 로그인 페이지로 리다이렉트.
2. **인증서 로그인은 사용자(교사 본인)가 직접 수행**한다(자동화 금지 영역).
   상세는 스킬 `neis-automation`의 1~3단계와 동일하다.
3. 업무포털 메인 상단 메뉴에서 **[교데통]** 클릭 → **새 탭**이 열리고 `sen.edmgr.kr/taskPotlMain`로 SSO 자동 로그인.
   창 폭이 좁으면 [교데통]이 잘려 보이므로 `find`로 링크 ref를 잡는 편이 빠르다.
4. 상단 메뉴 **데이터취합 > 제출자료**. (하위: 요청자료 / 제출자료 / 수신자관리 / 기관요청자료 / 기관제출자료 / 서식목록 / 요청자료인계인수 / 제출자료인계인수)

교데통 메인에 처음 들어가면 **공지 팝업이 두 겹으로 뜬다**(바깥: 기능개선 안내 / 안쪽: 데이터취합 서비스 운영 관련 안내). 안쪽부터 × 로 닫는다. 각 팝업 하단에 "오늘 열지 않음 / 다시 열지 않음" 체크가 있으나 임의로 켜지 말 것.

세션 타이머는 60분이고, **같은 브라우저 프로필의 새 탭에서는 `sen.edmgr.kr` 세션이 공유된다**(업무포털 로그인 탭과 달리 재로그인 불필요). 타이머는 화면이 전환될 때마다 60분으로 리셋되므로, 한 화면에 오래 머물며 다이얼로그만 만지고 있으면 남은 시간이 계속 줄어든다.

## 화면 구조

제출자료 화면은 상단에 `요청자료명` 검색 + [조회], 아래에 탭 5개다.

`기관접수대기(N)` / `내담당(N)` / `제출완료(N)` / `종료(N)` / `강제종료(N)`

목록 열: 제출번호 / 요청자료명 / **데이터취합구분** / 진행상태 / 요청기관 / 요청자 / 제출기관.

- **기관접수대기 목록은 기관(부서) 내 전체 직원에게 보여지고, 누군가 접수하면 나머지 직원의 목록에서 사라진다.** 화면 상단 붉은 안내문에 명시돼 있다. 남이 먼저 접수하면 내 목록에서 사라지므로, 안 보인다고 "요청이 없다"고 단정하지 말 것.
- 상단 상태바에 `데이터취합(기관접수대기 N · 내담당 N)` 카운터가 있어 조작 전후 대조에 쓰기 좋다.
- 건수가 많으므로(실측 36건) **요청자료명에 키워드를 넣고 [조회]** 하는 것이 가장 빠르다. 한글 타이핑 정상 동작.

## 제출 절차 (단계별)

### ① 요청 확인

`기관접수대기` 탭에서 요청자료명 키워드로 조회 → 해당 행의 **요청자료명 링크**를 클릭해 "데이터취합 작성상세"로 들어간다.

여기서 **반드시 먼저 확인할 3가지**가 제출 정보 표에 있다.

- **데이터취합구분** (목록 열): `파일`이면 파일취합, `서식`이면 웹 서식 셀 입력.
  〔매뉴얼〕 요청기관이 고르는 값은 셋이다: **파일취합 / 사용자지정서식 / 데이터관리카드**. 사용자지정서식은
  다시 `서식`과 `서식+파일`로 갈리므로 **서식을 다 채우고도 파일을 따로 올려야 하는 건이 있다.**
  데이터관리카드는 주기적 취합·시각화 분석용이라 학교 제출자가 만날 일은 드물다.
- **제출방법**: `전자결재` / `내부승인` / `바로제출`. 요청기관이 정해 둔 값이라 **제출자가 바꿀 수 없다.**
- **집계종료방법**: `종료일 YYYY-MM-DD HH시MM분`. **공문 본문의 마감 시각과 다를 수 있다**(실측: 공문 16:00 / 시스템 18:00). 더 이른 쪽인 공문 기준으로 움직인다.
  〔매뉴얼〕 종료방법에는 **`선착순`도 있고, 선착종료기준에 걸리면 종료일시 전에 마감된다.** 종료일만 보고
  안심하지 말고 종료방법 자체를 확인할 것.

작성요령(요청기관이 적은 안내문)과 **참고문서**(서식 파일 등 내려받을 자료), **제출파일**(내가 올릴 자리)도 이 화면에 있다.

### ② 요청 접수

좌측 패널 **[접수]** → *"데이터취합 제출 담당자로서 접수하시겠습니까?"* → [예] → *"접수이(가) 완료되었습니다."*

- 좌측 "접수저장 전에 꼭 확인하세요!"를 누르면 뜨는 설명: *"접수저장은 해당 데이터취합 요청 건의 열람여부를 판단하는 기준입니다. 접수 저장 후, 내담당으로 해당 요청 건을 제출하거나 해당없음으로 데이터 작성을 거절할 수 있습니다."*
- 접수 후 좌측 버튼이 **[접수취소] [해당없음] [담당자변경] [담당자변경이력] [제출]** 로 바뀐다. **[접수취소]가 있으므로 접수는 되돌릴 수 있다.**
- 카운터가 `기관접수대기 N-1 · 내담당 N+1`로 바뀌는지로 검증.
- 데이터취합 대상이 개인으로 지정된 경우 접수 없이 바로 내담당 탭에 뜬다.
- 〔매뉴얼〕 접수 후 좌측에 **[연계등록]**이 보이면 그 기관이 **연계등록기관(중간집계자)**으로 지정된 건이다.
  받은 취합을 하위 대상에게 다시 배포하는 기능이고, 이때 집계종료방법·데이터취합구분·시행방법·제출방법은
  고칠 수 없다. 일반 제출 건에는 나타나지 않는다.

### ③ 제출자료 작성

데이터취합구분에 따라 갈린다.

**파일취합**: 화면 하단 `제출파일` 영역(첨부 총 용량 5MB)에 파일을 넣는다. 아래 「파일 첨부 방법」 참조.

**사용자지정서식(웹 서식)**: 셀에 직접 입력한다. **엑셀에서 복사/붙여넣기는 통하지 않는다.** 셀마다 입력 형식(정수·소수·문자·날짜·목록)과 유효성 조건이 걸려 있어 붙여넣기로는 검증을 통과하지 못하고, 미입력 셀이 남으면 제출 단계에서 `CM999`("데이터취합 자료제출을 위한 서식 파일생성이 정상처리되지 않았습니다") 오류가 난다. 셀을 하나씩 클릭해 입력해야 한다.
- 이 웹 서식 표는 **스크린 리더 접근성이 매우 나쁘다**(실측). 마감이 촉박하면 (1) 동료에게 화면을 보며 셀별 입력을 부탁하거나 (2) 취합 요청 담당자에게 접근성 문제를 설명하고 엑셀 파일 대체 제출이 가능한지 문의하는 편이 현실적이다.
- 공문에 "파일 제출"로 적혀 있으면 대개 파일취합이므로, 이 고생은 하지 않아도 된다. **공문 문구와 목록의 데이터취합구분 열을 먼저 대조할 것.**
- 〔매뉴얼〕 서식은 **가변양식**과 **고정양식**으로 갈린다. 가변양식은 제출자가 행을 추가·삭제할 수 있고,
  고정양식은 정해진 영역에만 입력한다. 행이 모자라 보이면 먼저 가변양식인지(행추가가 되는지) 확인한다.
- 〔매뉴얼〕 요청기관이 셀마다 **설명**을 달아 둘 수 있고 그 셀에 입력할 때 표출된다. 유효성 조건도 요청기관이
  건 것이라 조건을 벗어난 값은 **아예 입력되지 않는다.** 값이 안 들어가면 오타가 아니라 유효성 조건을 의심할 것.

**열람제한·열람범위는 저장 전에 반드시 선택해야 한다.** 둘 다 초기값이 비어 있고, 안 고르고 저장하면 *"열람제한 및 열람범위 을(를) 설정 후 저장하십시오."* 알림이 뜬다.
- `열람제한` = 설정 / 설정안함, `열람범위` = 개인 / 기관. 온라인도움말은 캡처 이미지뿐이라 설명이 없다.
- 부서 공동 업무(부장·관리자가 열람·인계해야 하는 건)의 기본값은 **설정안함 + 기관**. 저장 후에도 다시 고칠 수 있다.
- 이 라디오는 커스텀 DIV라 `document.querySelectorAll('input[type=radio]')`가 **빈 배열**이다. 좌표 클릭 후 `zoom`으로 선택 상태(파란 점)를 확인할 것.

**[임시저장]** 과 **[저장]** 이 따로 있다. 제출을 나중에 할 거면 [임시저장]으로 서버에 올려 둔다.
- [임시저장] → *"임시저장 하시겠습니까?"* → [예] → 업로드 진행 바("파일 업로드 프로세스를 시작합니다" → "완료") → **"임시저장 되었습니다."**
- 저장 알림까지 **3~5초 지연**되므로 화면이 그대로여도 기다렸다 재스크린샷할 것.
- 저장 후 내담당 탭의 진행상태가 `미작성` → `임시저장`으로 바뀐다.

### ④ 제출

좌측 **[제출]** → 제출방법(요청기관이 지정한 값)에 따라 진행.

- **전자결재**: K-에듀파인(업무관리) 결재 연동. 결재완료 = 최종 제출. 결재라인 사전 확인 필수.
  〔매뉴얼〕 이 방식은 **K-에듀파인에서 그 공문을 접수한 사람이 교데통 담당자로 자동 지정**되므로 교데통에서
  따로 [접수]를 누를 일이 없다.
- **내부승인**: 교데통 자체 내부결재. **K-에듀파인 기안이 필요 없다.** 아래 「내부승인 결재 상신」 참조.
- **바로제출**: 승인 없이 즉시 제출.

제출은 되돌리기 번거로운 대외 행위이므로, **첨부·설정을 요약해 사용자에게 확인받은 뒤** 누른다.

임시저장 상태로 며칠 묵혀 둔 건이라면 [제출] 전에 **서버 첨부본이 최신인지 반드시 대조**한다. 임시저장 뒤에 원본을 고쳤다면 구버전이 올라가 있다. 목록 화면에는 파일 크기가 KB 단위로만 보이므로, 로컬 파일의 바이트 수와 대조하고(8,953바이트 ↔ 8.7 KB) 내용도 한 번 열어 확정값이 들어 있는지 확인한다.

#### 내부승인 결재 상신

[제출]을 누르면 `[요청자료명] 내부승인` 다이얼로그가 뜬다. **이 화면이 실질적인 기안이다.**

- 업무구분(데이터제출), 제목, 요청자, 요청일자, 내용이 **자동으로 채워져 나온다.** 손댈 필요가 없다.
- 할 일은 **결재선 조립뿐**이다. 기본값은 기안자 1명뿐이라 그대로 두면 안 된다.
- [결재자추가] → "사용자 검색" 팝업. 좌측은 조직도 트리, 우측 상단에 **소속 학교 사용자 목록이 이미 떠 있다**(교장·교감·행정실장·부장교사 순). 별도 검색 없이 체크 → [추가] → [적용].
- **결재순서가 꼬이지 않도록 한 명씩 체크·추가한다.** 추가한 순서대로 결재순서 2, 3, 4가 매겨진다.
- **그리드는 역순 표시**다. 안내문 1번 "최종 결재자가 상위에 표시됩니다"가 그대로 적용돼 맨 위 행이 최종 결재자, 맨 아래가 기안자다.
- **결재구분은 위치에 따라 자동 재배정**된다(기안 / 검토 / … / 결재). 안내문 2번 "최종 결재자의 결재구분은 결재 또는 전결이여야 합니다"는 순서만 맞추면 저절로 충족된다.
- [승인요청] → "승인요청하시겠습니까?" → [확인] → **"승인요청이 완료되었습니다."**
- 검증: 작성상세 좌측 버튼이 **[담당자변경이력] [제출취소]** 로 바뀌고, 상단 상태바 `내부승인(요청 N)`이 +1 되며, [목록] → 내담당 탭 진행상태가 `임시저장` → **`제출진행`**.
- 되돌리려면 좌측 **[제출취소]**.

### ⑤ 제출자료 관리 / ⑥ 재작성(회수요청)

상신 직후에는 아직 `내담당` 탭에 `제출진행` 상태로 남아 있다. **결재가 모두 끝나야 `제출완료` 탭으로 넘어간다.** 마감 전에 한 번 더 들어가 탭 이동을 확인할 것.

진행상태 흐름: `미작성` → `임시저장` → (제출·상신) `제출진행` → (결재완료) `제출완료`.

`제출완료` 탭에서 상태 확인. 수정이 필요하면 [회수요청] → 자동회수 설정 건은 즉시 회수, 아니면 요청자 승인 후 회수 → 내담당 탭에서 수정 후 재제출.

아직 결재가 진행 중이라면 회수요청까지 갈 것 없이 작성상세 좌측 **[제출취소]**로 상신을 내린 뒤 고쳐서 다시 올리는 편이 빠르다.

## 파일 첨부 방법 (Uppy 업로더 — 자동화 핵심)

제출파일 영역은 **`iframe[src*="fileMultiUploadDownload"]` 안의 Uppy 업로더**다. 한 화면에 참고문서용·제출파일용 iframe이 **두 개** 있으니 인덱스를 헷갈리지 말 것(제출파일 쪽이 뒤에 온다. `getBoundingClientRect()`의 y로 판별).

[파일선택] 버튼을 누르면 네이티브 "열기" 대화상자가 열리는데 **자동화로 조작할 수 없다**(스크린샷에도 안 잡히고, 반복해서 누르면 창이 쌓인다). 누르지 말 것.

확인된 경로 — 최상위 문서에 임시 input을 만들어 다리를 놓는다. (a11y 트리가 iframe 내부로 내려가지 않아 Uppy input에 직접 ref를 못 붙인다)

1. 최상위 문서에 임시 file input 생성 (`find`가 잡도록 `aria-label`을 붙이고 화면에 보이게 스타일 지정)
   ```js
   const t=document.createElement('input'); t.type='file'; t.id='__tmpUp';
   t.setAttribute('aria-label','임시업로드입력');
   t.style.cssText='position:fixed;top:10px;left:10px;z-index:999999;width:300px;height:30px;';
   document.body.appendChild(t);
   ```
2. `find`로 ref를 얻어 **`file_upload` 도구로 실제 파일을 넣는다.**
3. iframe 컨텍스트의 `DataTransfer`로 옮기고 `change`를 디스패치한다.
   ```js
   const src=document.getElementById('__tmpUp');
   const f=[...document.querySelectorAll('iframe')].filter(x=>x.src.includes('fileMultiUploadDownload')).pop();
   const w=f.contentWindow, d=f.contentDocument;
   const inp=d.querySelector('input.uppy-Dashboard-input');
   const dt=new w.DataTransfer(); dt.items.add(src.files[0]);
   inp.files=dt.files; inp.dispatchEvent(new w.Event('change',{bubbles:true}));
   ```
4. **`inp.files.length`가 다시 0으로 보이는 것은 정상**이다. Uppy가 파일을 읽어 간 뒤 input을 비운다. 성공 여부는 반환값이 아니라 화면의 **"1개의 파일 선택됨" + 파일명·용량**으로 판단한다.
5. **임시 input을 지운다** (`__tmpUp`.remove()). 안 지우면 화면 좌상단에 남아 헤더를 가린다.
6. 이 시점의 첨부는 **아직 클라이언트에만 있다.** [임시저장]/[저장]까지 눌러야 서버에 올라간다. 저장 후 목록 → 재진입으로 파일이 남아 있는지 최종 검증할 것.

## 자동화 시행착오 메모

- **`javascript_tool`의 `document.body.innerText`가 화면 전체를 못 준다.** 이 앱은 목록이 `<table>`이 아니고 라우팅으로 DOM이 교체돼, 같은 코드를 두 번 돌리면 결과 길이가 크게 달라진다. 목록·상세 판독은 스크린샷을 우선하고, JS는 첨부 조작과 값 검증 위주로 쓸 것.
- **상단 메뉴 드롭다운이 stale하게 남는다.** 새 탭을 만들어 메뉴를 다시 열면 직전 메뉴(예: 데이터활용)가 계속 표시되며 클릭이 엉뚱한 데로 간다. 탭을 새로 파기보다 **작업 탭 하나에서 [목록] 버튼으로 오가는 편이 안전**하다.
- **창 크기가 도중에 바뀌면 좌표가 전부 어긋난다**(실측: 958×888 → 1151×1067 → 1156×1063). 클릭 전 항상 최신 스크린샷으로 좌표를 다시 잡을 것.
- 다이얼로그 버튼은 대개 좌표 클릭이 통하지만, **뷰포트가 축소(브라우저 줌 아웃)되면 스크린샷 좌표와 CSS 좌표가 어긋나 클릭이 통째로 빗나간다.** 실측: `devicePixelRatio 0.75`, `innerWidth 1277`인데 스크린샷은 1156px(비율 0.905). 이 상태에서는 스크린샷에서 읽은 좌표로 눌러도 아무 일이 일어나지 않는다.
  - 판별: `javascript_tool`로 `{iw:innerWidth, ih:innerHeight, dpr:devicePixelRatio}`를 찍어 스크린샷 크기와 비교한다. 비율이 1이 아니면 좌표 클릭을 포기한다.
  - **더 신뢰할 수 있는 우회는 DOM 이벤트 디스패치다.** 이 앱(`cl-*` 클래스의 CL 프레임워크)에서 실제로 통한 코드:
    ```js
    const t = [...document.querySelectorAll('div.cl-text')]
      .filter(x => x.offsetParent && x.innerText.trim() === '확인').pop();
    const btn = t.closest('[role=button]');           // 실제 클릭 대상
    const r = btn.getBoundingClientRect();
    const o = {bubbles:true, cancelable:true, view:window, button:0,
               clientX:r.x+r.width/2, clientY:r.y+r.height/2,
               pointerId:1, isPrimary:true, pointerType:'mouse'};
    setTimeout(() => ['pointerdown','mousedown','pointerup','mouseup','click']
      .forEach(n => btn.dispatchEvent(
        new (n.startsWith('pointer') ? PointerEvent : MouseEvent)(n, o))), 0);
    ```
    `pointerdown`까지 포함해야 반응한다. `click()`이나 `MouseEvent('click')` 단독은 무시된다.
  - **버튼 텍스트는 `<button>`이 아니라 `div.cl-text`에 들어 있다.** `querySelectorAll('button')`로 "확인"을 찾으면 빈 배열이 나오므로 없는 줄 알고 헤매기 쉽다. 클릭 대상은 조상의 `[role=button]`(`cl-control cl-button`).
- **스크린샷이 stale하게 굳는 일이 있다.** 창 크기가 바뀐 직후 연속 캡처가 이전 프레임을 계속 돌려줘, 이미 닫힌 다이얼로그가 화면에 남아 있는 것처럼 보였다. 화면 상태 판정은 스크린샷만 믿지 말고 `javascript_tool`로 교차 확인한다. 예: 팝업 잔존 여부 `[...document.querySelectorAll('div.cl-text')].filter(x=>x.offsetParent&&/하시겠습니까|되었습니다/.test(x.innerText))`, 진행 검증 `document.body.innerText.match(/데이터취합\([^)]*\)/)`.
- 저장 전 데이터는 클라이언트에만 있다. **탭이 유실되면 첨부·설정이 전량 소실**되므로 조작이 끝나면 바로 [임시저장].

## 공문 기반 제출 안내 작성 절차

사용자가 공문을 제공하고 교데통 제출 안내를 요청하면:

1. 공문에서 추출할 정보: 제출서류명·서식 파일 / 제출기한(날짜·시각) / 제출방법 / 발송기관 / 근거 공문번호 / 문의처
2. 해당 폴더에 `교데통 제출 안내.txt` 작성
3. 포함 내용: 제출 개요, 접속 방법, 제출 경로, 단계별 절차, 결재 방식, 유의사항
4. **제출방법·데이터취합구분은 공문 문구만 믿지 말고 교데통 화면에서 확인해 확정할 것.** 공문에 "파일 제출"이라고만 적혀 있어도 시스템에서 전자결재인지 내부승인인지는 알 수 없다.

## 결재라인 (학교별 확인)

- 일반형: 담당교사(기안) → 부장교사(검토) → 교감(검토) → 교장(결재) 4단계
- 간이 결재: 담당교사 → 부장교사 (건별 상이)
- 기한 마감 전 여유 있게 상신 (결재완료까지 시간 소요)

내부승인 결재선의 실제 계정 구성은 학교마다 다르다. [결재자추가] 사용자 검색 팝업 우측에
**소속 학교 사용자 목록이 직위순(교장·교감·행정실장·부장교사 …)으로 이미 떠 있으므로**,
처음 쓰는 학교라면 그 목록에서 자기 부서 결재라인을 확인해 기록해 두면 다음부터 빠르다.

## 유의사항

- 제출기한 이후 제출 불가 → 여유 있게 결재 상신. 강제종료된 건도 제출 불가.
- 담당자 변경 필요 시: 접수 후 [담당자변경] 활용. 이력은 [담당자변경이력]에서 확인.
- 해당 건이 학교와 무관하면 [해당없음]으로 거절 가능.
- 제출자료 부서 공유 설정으로 같은 부서 교직원과 공유 가능.

  - 시스템 집계종료(18:00)가 공문 마감(16:00)보다 늦었다.
  - Uppy iframe 업로더 우회 경로(위 「파일 첨부 방법」)가 유효했다.
- **2026-08-18 · 같은 건 상신 완료 (내부승인 4단계)** — 임시저장 건을 열어 [제출] → 결재선 조립 → [승인요청]까지 실제 수행하고 「내부승인 결재 상신」 절차를 정립. 확인 사항:
  - 내부승인 화면은 제목·요청자·내용이 자동 생성되므로 **결재선만 조립하면 끝난다.** 결재구분도 위치에 따라 자동 배정된다.
  - 결재선 그리드는 **역순 표시**(맨 위가 최종 결재자). 나이스 결재선과 같은 방식.
  - 상신 검증 3종: 좌측 버튼이 [제출취소]로 전환 / 상태바 `내부승인(요청 +1)` / 내담당 탭 진행상태 `제출진행`.
  - 임시저장 후 4일이 지난 건이라 **서버 첨부본이 최신인지 로컬 파일 바이트 수로 대조**했다(8,953바이트 ↔ 8.7 KB, 일치).
  - 뷰포트 축소로 **좌표 클릭이 전부 빗나가** DOM 이벤트 디스패치로 우회했다. 자세한 내용은 「자동화 시행착오 메모」.
- **2026-08-19 · 같은 건 결재 완료 확인 (제출완료)** — 상신 다음 날 결재 진행 상황을 조회하며 완료 판정법을 정립. 확인 사항:
  - **가장 빠른 판정은 제출자료 화면의 탭 카운터**다. `내담당(0)` + `제출완료(N)`이면 결재가 끝나 넘어간 것이고, 상단 상태바 `내부승인(요청 0 · 처리 0)`도 같이 0이 된다. 목록 행의 진행상태도 `제출완료`로 바뀐다.
  - 작성상세 좌측 버튼이 `[담당자변경이력] [내부승인현황] [회수]`로 바뀐다. **[제출취소]가 사라지고 [회수]가 나타난 것이 완료 신호**다(결재 중에는 [제출취소]).
  - **[내부승인현황]을 누르면 "승인요청상세"에 결재자별 승인일시·의견·결재구분이 전부 나온다.** 진행상태에 `승인완료 (YYYY-MM-DD HH:MM)`이 찍히고, 결재선 그리드는 여기서도 역순(최종 결재자가 맨 위). 실측: 기안 8-18 13:31 → 부장 검토 16:05 → 교감 검토 16:45 → 교장 결재 8-19 09:04. **교감까지 당일, 교장 결재가 다음 날 오전**이었으므로 마감 당일 상신은 위험하다.
  - 상세 우상단 [붙임(제출자료)]로 실제 제출된 첨부를 다시 확인할 수 있다.
  - 세션은 브라우저 프로필 간 공유되지 않는다. `sen.edmgr.kr`에 직접 들어가면 자체 로그인 화면이 뜨고, `sen.edmgr.kr/taskPotlMain`을 URL로 직접 치면 세션이 없어 **"페이지를 찾을 수 없습니다"**가 난다. 업무포털 인증서 로그인 → 상단 [교데통] 경로를 그대로 밟아야 한다.
