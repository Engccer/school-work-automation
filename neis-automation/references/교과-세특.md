# 교과 세특 입력 — 과목별세부능력및특기사항

교과담당교사가 학생 한두 명의 교과 세특을 화면에서 직접 입력하는 절차(전출 예정 학생의
조기 기록 등). 반 전체를 넣을 때는 세특양식 CSV 일괄 반영 경로가 낫고, 이 절차는 소수 입력용이다.
문안 자체는 학교생활기록부 기재요령을 따른다.

1. **메뉴**: 교과담임 → **성적 > 성적처리 > 과목별세부능력및특기사항**.
2. **조회 조건**: 학년도·학기·학년·과목·**강의실(=반)** 모두 필수, 드롭다운은 커스텀 DIV다
   (SKILL.md 일반 팁 「커스텀 드롭다운」).
   학년 목록에는 그 학기 담당 학년만 나온다. 과목명은 교육과정 편제 이름으로 나오므로
   (예: 수업에서 부르는 이름과 달리 단일 교과명) 목록에 있는 것을 고른다. `영재 미표시`는 기본 체크.
3. **한도는 `1, 2학기 합쳐서 1500 Byte`(500자)** 이고 화면에 `N / 1500 Byte`로 표시된다.
   1학기 기록이 있는 학생은 남은 Byte가 줄어 있다(예: `0 / 1090 Byte`). 학생마다 `일반`·`영재`
   두 행이 있으며 교과 세특은 **일반** 행에 넣는다.
4. **세로 스크롤이 이 화면의 최대 난관이다.** 그리드 위 마우스 휠은 그리드가 아니라 페이지를
   움직이고, 스크롤바 썸 드래그는 썸만 움직이고 행이 갱신되지 않거나 몇 행만 움직인다.
   이 화면에서는 휠·썸 드래그를 시도하지 말고 SKILL.md 일반 팁 「그리드 스크롤」 3번의
   **JS `scrollTop` + `scroll` 이벤트** 방식으로 바로 이동한다. 목표 행 위치는
   `(번호−1)/전체인원 × scrollHeight`로 어림잡고 스크린샷으로 확인한다.
5. **입력**: SKILL.md 일반 팁 「학생부 텍스트 그리드 편집」 순서로 **일반** 행 칸을 더블클릭 →
   대기 → 캐럿 확인 → **별도 호출로 `type`**.
   셀에 포커스가 가면 **그리드가 가로로 밀려 성명 열이 화면 밖으로 사라진다** — 행 확인은
   입력 전 스크린샷의 반/번호·성명으로 미리 해 두고, 입력 중에는 하이라이트된 행으로 판단한다.
6. **검증**: 편집 중인 칸은 `textarea`/`input`으로 렌더링되므로 JS로 `value`를 읽어
   **원고와 완전 일치 비교**가 된다. 이어 학적변동구분 등 중립 셀을 클릭해 커밋하면
   `N / 1500 Byte`가 갱신된다(한글 3Byte·그 외 1Byte 기대값과 대조). 성명 클릭은 금지
   (1·2학기 입력 내용 출력 화면이 열린다).
7. **[저장]** → "저장하시겠습니까?" → [확인] → "자료의 저장이 완료되었습니다." → [확인].
   확인 창은 늦게 뜨고 **뜬 직후 위치가 한 번 옮겨진다** — 첫 스크린샷 좌표로 누르면
   빗나간다. JS로 보이는 `확인` 요소의 `getBoundingClientRect()` 중심을 구해 SKILL.md 일반 팁
   「좌표 환산」으로 스크린샷 좌표로 바꿔 누른다(「확인·완료 다이얼로그」 1번).
   `find`가 돌려주는 이름 없는 버튼 ref는 확인/취소 구분이 불확실하니 쓰지 않는다. → 사례
8. **최종 검증은 [조회] 재실행 후 4번 방식으로 그 행에 가서 Byte와 본문을 확인**한다.
