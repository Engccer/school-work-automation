## 사전 점검 (브라우저 연결)

- 연결된 브라우저 목록 조회 이름 밀림: 선택 직후 응답이 다른 이름을 돌려주고, 재조회하니
  목록이 3개로 늘며 이름이 한 칸씩 밀렸다(v2.6).
- 창이 작게 잡힌 실측: 높이 276~322px.
- 확장 연결 지연: 첫 요청 시 수 분간 `[]`였다가 이후 연결됐다(v1).
- 4단계 [나이스] 메뉴에는 "1568px 폭 기준 약 (320, 68)"이라는 고정 좌표 예가 있었으나 지웠다.
  K-에듀파인 쪽에서 창 폭에 따라 메뉴가 줄바꿈돼 옛 좌표가 다른 메뉴를 누른 실측이 있다.

## 나이스 화면 조작 일반 팁

- 학생부 텍스트 그리드: 동아리 특기사항 입력 때 8명을 넣은 뒤 탭이 사라져 전량 재입력했다(v1.3).
- 입력값 검증: 외부강의 신고 입력에서 CDP 한글 타이핑이 `워크숍`을 `워크숨`으로 망가뜨렸다(v1.9).
- 그리드 스크롤: 교과 세특 화면에서 휠은 페이지를, 썸 드래그는 썸만 움직여 목표 행이 그려지지
  않았고 JS `scrollTop` + `scroll` 이벤트로 해결했다(v2.9). 창 크기 조정으로 창을 키워도 뷰포트가
  1044×619로 고정된 채였다.
- 확인·완료 다이얼로그 지연 실측값(일반 팁의 3~15초 범위의 근거): OMR 일괄채점·동아리 특기사항
  저장 3~5초, 외부강의 현황 알림 4~5초, 외부강의 신고 상신의 확인·완료 8~15초, 근무상황 [상신]·
  [회수]·[삭제] 알림 5~10초, 독서활동 저장 확인 창 약 9초(5초 대기로는 못 잡았다), 학기 시작
  수행평가영역 저장 10초 넘게, 교과 세특 저장 5~9초(뜬 직후 위치 이동).
  다이얼로그 버튼 대체 수단도 절마다 달랐다: 동아리 특기사항은 "좌표 클릭이 먹히지 않는 경우가
  많아 find ref 또는 JS click()", 근무상황은 "좌표 클릭이 통한다(안 되면 find ref)", 교과 세특은
  "이름 없는 find ref는 확인/취소 구분이 불확실". 2.10.0에서 좌표 → JS click() → 이름 있는 find
  ref 순서 하나로 정했다.
- 좌표 환산: 접근성 트리 읽기 viewport 1920px와 스크린샷 1568px에서 ×0.817, 교과 세특 저장 확인 창에서
  ×1.25가 나왔다. 세션·창마다 다른 값이라 상수로 쓰지 않는다.
- 확대 캡처 타임아웃: 고착 시 `window.innerWidth`가 확대 캡처 영역 크기(예: 182×25)였다. v1.9(외부강의
  신고)에서는 창 크기 조정으로 복구되지 않아 탭 재생성이 유일한 복구라고 적었고, 같은 날 v2.1(출장
  신청)에서는 창 크기 조정으로 복구됐다.
- 공지 팝업: 나이스에서 공지가 2개 연속으로 떴다(v2.7).
- Chrome 팝업 창 열거: 정부24 [문서출력] 팝업의 실제 창 제목은 「정부24 - 문서출력 - Chrome」였다(v2.8).

## 상신 공통 — 선례 확보·결재선 조립·되돌리기

- [복사]로 재상신한 뒤 원 `상신취소` 행이 총계에 남아 4시간이 중복 계상됐다(근무상황, v1.8).
- 개인 결재선 팝업 관찰의 변천: v1.7 "행을 클릭해도 우측 패널이 직전 선택을 유지" → v1.8 "행
  하이라이트와 로드되는 결재선이 어긋남, [지정] 결과는 패널과 일치"로 정정 → v1.9 외부강의 신고에서
  "같은 행을 두 번 눌러야 뜨기도 하고, 팝업을 닫았다 열어도 재현이 일정하지 않다"며 [결재자지정]
  직접 조립을 권고 → v2.1 출장도 [결재자지정]. 근무상황 절만 [개인결재선]을 기본으로 남아 있어
  2.10.0에서 [결재자지정] 기본·[개인결재선] 보조로 통일하고, "[지정] 결과는 패널과 일치"라는 v1.8
  단정은 v1.9의 불안정 관찰과 맞지 않아 검증을 결재선 그리드로만 하도록 바꿨다.
- 상신 전 사용자 확인은 외부강의(저장 뒤)·근무상황(14번, [승인요청]·[상신] 뒤에 놓여 있었다)에만
  있고 출장에는 없었다. 2.10.0에서 확인 ①([승인요청] 전)·② ([상신] 전) 두 지점으로 일반 원칙에
  올렸다.
- `상신취소` 행 삭제는 근무상황 절에서 "정리하려면"(선택), 출장 절에서 "[삭제]한다"(절차)로 달랐다.
  2.10.0 개정 후 시험에서 이 차이가 충돌로 잡혀 재상신 절차의 마지막 단계로 맞추고, 되돌릴 수 없는
  삭제라 확인 ①에서 함께 알리게 했다.

## 교과 세특 입력 — 과목별세부능력및특기사항

- [저장] 확인 창이 5~9초 뒤에 떴고 뜬 직후 위치가 옮겨졌다. JS rect 좌표를 ×1.25로 환산해
  눌렀다(v2.9, 비율은 그 세션 값).
- 2026-10-14 EVPN 원격 입력: 브라우저 제어 확장이 업무포털·구글·example.com 모든 탭에서
  `Cannot attach to this target`. 새 탭, 탭 그룹 재생성, 사이드 패널 탭 정리, 크롬 프로세스 완전 재시작
  모두 효과 없었고 크롬 정책·디버거 권한 확장(ChatGPT·axe DevTools)에서도 원인을 못 찾았다. 앱 내장
  브라우저는 인증서 프로그램 미인식. Playwright 크롬으로 바꾸자 인증서 로그인 → 나이스 SSO →
  입력·저장·재조회까지 막힘 없이 끝났다(insertText 1회로 원고 완전 일치, 저장 확인 창 수 초 지연은 동일).
  업무포털 로그인 세션은 같은 크롬 안에서는 새 탭에서도 유지됐다(탭 단위 세션이라는 2단계 서술과 다름).
  AXGATE VPN 클라이언트가 띄우는 "로그인 후 자동 실행" 창(`#32770`)은 닫아도 터널에 영향 없다.
  그날 마지막으로 쓴 크롬 프로필은 학교 Workspace 계정 프로필이었고, 그 프로필에만 클라우드 사용자
  정책(`Policy/User Policy`, Claude 확장 ID 포함)이 내려와 있었다. 정책 파일에서 `DeveloperToolsAvailability`
  같은 차단 키를 직접 확인하지는 못해, 관리 정책 원인설은 가설로 남겼다. 개인 계정 프로필 크롬에서도
  막히는지 보면 가를 수 있다.
- 2026-10-18 확정: 같은 학교 프로필에서 F12를 누르자 "조직에서 이 페이지의 DevTools 사용을 차단했습니다"가
  떴다. 개발자 도구를 막는 관리 정책이 원인이다. 개인 계정 프로필을 쓰는 다른 교사의 PC에서도 같은
  `Cannot attach` 증상이 보고됐다(PC 단위 정책으로 추정, 개발자 도구 미확인). 같은 PC에서 Playwright로는
  업무포털 인증서 로그인과 나이스 진입까지 됐다.

## 변경 이력

각 항목은 그 버전 당시의 판단 기록이다. 뒤 버전에서 뒤집힌 서술도 그대로 두며, 현행 규칙은 SKILL.md와
업무 파일이 정본이다.

- v2.10.0 (2026-10-08): **구조 정리(스킬 감사).** 업무별 절을 `references/<업무>.md`로 나누고 SKILL.md에는
  진입·일반 팁·일반 원칙과 업무 목차만 남겼다. 변경 이력과 본문 속 경위·실측 수치는 이 파일로 옮겼다.
  결재선은 [결재자지정] 직접 조립을 기본으로 통일하고, 상신 전 사용자 확인을 두 지점(확인 ①
  [승인요청] 전, 확인 ② [상신] 전)으로 일반 원칙에 올렸다(출장 절에 없던 확인 추가, 근무상황 절의
  확인 위치 정정). 선례 확보·결재선·회수·[복사]는 `references/상신-공통.md` 하나로 모았다. 일반 팁에
  날짜 입력 3유형·학생부 텍스트 그리드 편집·확인 다이얼로그 순서와 지연·좌표 환산(비율을 매번 계산)·
  확대 캡처 고착 복구(창 크기 조정 먼저)·그리드 스크롤 순서·브라우저 제어 확장 공통 함정을 모았다.
  "세특"은 교과 세특에만 쓰도록 독서활동 절의 비교 대상을 동아리 특기사항으로 바로잡았다.
  급여명세서 절은 openpyxl 의존성, CSV 앞 3행 메타, 스크립트 검산 4종과 사람이 대조할 `ym`을 나눠 적었다.
- v2.9 (2026-10-02): **교과 세특 입력(과목별세부능력및특기사항) 워크플로우 추가** — 전출 예정
  학생 1명의 교과 세특을 EVPN 원격 접속으로 입력·저장·재조회 검증하며 정립. 한도는 **1·2학기 합산
