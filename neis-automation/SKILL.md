# 나이스 업무 자동화 (업무포털 → 나이스 진입)

## 개요

서울특별시교육청 업무포털을 거쳐 4세대 나이스에 진입하는 브라우저 자동화 워크플로우.
기본 브라우저는 Playwright가 띄우는 크롬이다(→ 「브라우저 준비」). **인증서 로그인은 반드시 사용자(교사 본인)가 직접 수행**한다
(인증서 비밀번호 입력은 자동화 금지 영역).

- 업무포털: `https://sen.eduptl.kr/bpm_man_mn00_001.do` (메인) / `bpm_lgn_lg00_001.do` (로그인)
- 나이스: `https://sen.neis.go.kr/jsp/main.jsp` (업무포털에서 SSO로 진입)

⚠ **재직증명서 등 교육제증명은 이 경로가 아니다.** 공인망의 나이스 대국민서비스
(`www.neis.go.kr`)를 거쳐 정부24에서 발급하며 업무포털·EVPN·교육행정 전자서명 인증서가
모두 필요 없다 → [references/교육제증명-정부24.md](references/교육제증명-정부24.md).

> **적용 범위**: 서울특별시교육청 환경(`sen.*` 도메인)에서 실사용으로 검증했다. 타 시도는
> 업무포털·나이스 서브도메인이 다르지만 4세대 나이스 화면 구조는 전국 공통이라 절차 골격은
> 그대로 적용된다.

## 원격(외부망) 접속 — EVPN

학교 밖(자택 등)에서 작업하거나 업무포털 주소 이동이 무응답이면 착수 전에 [references/EVPN.md](references/EVPN.md)를 읽는다.

## 브라우저 준비

**기본은 Playwright다.** 도구 로드·로그인·업무 시스템 진입은 [references/playwright.md](references/playwright.md)를
따른다. 아래 워크플로우의 사실(세션·팝업·화면 구조)은 두 경로에 공통이고, 이 문서와 업무 파일의
도구 이름은 확장 기준이라 Playwright 경로에서는 그 파일의 대응표로 바꿔 읽는다.

### 확장을 쓸 때(사용자가 원할 때)

1. 브라우저 제어 확장이 다음 기능을 제공하는지 확인한다: 탭 목록 조회, 주소 이동, 좌표 클릭과 화면 캡처,
   접근성 트리 읽기, 요소 찾기, 일괄 실행, 연결된 브라우저 목록 조회, 창 크기 조정, 페이지 JS 실행, 폼 값 설정.
   파일 업로드·페이지 텍스트 추출은 그것을 쓰는 업무에서 필요하다.
2. 연결된 브라우저 목록 조회로 연결 확인. **표시 이름(`Browser 1`, `Browser 2`…)은 그
   순간의 목록 순서로 붙는 라벨이라 고정된 식별자가 아니다.** 창이 하나 더 붙거나 빠지면
   같은 이름이 다른 창을 가리킨다. **판단은 `deviceId`로 하고**, 사용자에게
   물을 때도 이름과 함께 deviceId를 보여 준다. 잘못된 창을 잡으면 업무포털이
   `Frame with ID 0 is showing error page`로 뜨는데, 이때는 권한·네트워크 문제가 아니라
   **창을 잘못 고른 것**이므로 목록을 다시 뽑아 사용자에게 재확인한다. → 사례
   - 창이 작게 잡히면 스크린샷에 화면이 거의 안 담긴다.
     창 크기 조정으로 1600×1000 정도로 키우고 시작한다.
   `[]`(빈 배열)이면:
   - Chrome 실행 + 브라우저 제어 확장 연결 상태 확인을 사용자에게 요청
   - **연결에 시간이 걸릴 수 있음.** 사용자가 "확인해 봐"라고 할 때 재시도하면 잡히는 경우가 많다.
3. 탭 목록 조회(탭이 없으면 새로 만들게 한다) → 새 창+새 탭이 생성된다. 이 탭 ID로 이후 모든 조작을 수행.
4. **처음 여는 도메인(업무포털, 정부24 `plus.gov.kr` 등)의 첫 주소 이동·첫 동작이 한 번 거부될 수 있다(Claude in Chrome에서 실측).**
   `Permission denied for this action on this domain` 또는 `Navigation to this domain is not allowed`가
   뜨고 탭이 새 탭으로 되돌아가는데, **같은 동작을 한 번 더 하면 통과**한다(확장 도메인 권한이 뒤늦게
   적용되는 것으로 보임). 설정 문제로 오인해 사용자에게 권한 설정을 요청하기 전에 재시도할 것.
   - 단 일괄 실행 안에서 거부되면 **그 배치의 남은 액션이 전부 취소**되므로,
     재시도는 주소 이동 단독 호출로 한다.
   - 재시도해도 계속 막히면 도메인 자체가 무응답인 경우다. **EVPN 미연결과 구분**하려면
     PowerShell로 `Test-NetConnection sen.eduptl.kr -Port 443`을 확인한다
     (`TcpTestSucceeded: False`면 권한이 아니라 네트워크 문제 → 「원격(외부망) 접속 — EVPN」).

## 워크플로우

### 1단계: 업무포털 접속 → 로그인 페이지

- 주소 이동 → `https://sen.eduptl.kr/bpm_man_mn00_001.do`
- 미로그인 상태면 자동으로 `bpm_lgn_lg00_001.do` (로그인 페이지)로 리다이렉트된다.
- navigate 직후 스크린샷은 흰 화면일 수 있다. `wait 2~3초` 후 스크린샷을 찍을 것.

### 2단계: 세션 공유 안 됨 — 사용자 로그인 대기

- 사용자가 다른 탭/창에서 이미 업무포털에 로그인해 있어도,
  자동화 탭에서 `main.html` 등으로 직접 접근하면 **"해당 서비스 호출에 실패하였습니다"** 오류가 뜬다.
  이 포털은 로그인 절차를 거친 탭(창)에서만 세션이 유효하다. 기존 로그인 세션에 편승할 수 없다.
- 따라서 자동화 탭을 로그인 페이지(`bpm_lgn_lg00_001.do`)에 둔 상태로 사용자에게 요청:
  **"교육행정 전자서명 인증서 로그인" 버튼을 눌러 인증서 로그인을 직접 진행해 주세요.**
- 사용자가 이 탭에서 로그인하면 기존 탭 세션이 끊길 수 있음을 미리 안내한다(중복 로그인 제한 가능).
- 로그인 완료 통보를 받으면 탭 목록 조회 + 스크린샷으로 확인.
  성공 시 탭 제목 "업무포털 메인", URL `bpm_man_mn00_001.do`.
- 로그인 화면에 "인증서 로그인용 프로그램 설치가 필요합니다" 알림이 뜨거나 인증서 선택창에 인증서가 안 보이면 [references/인증서-로그인.md](references/인증서-로그인.md).

### 3단계: 업무포털 메인 — 공지 팝업 닫기

- 로그인 직후 KERIS 등 공지 팝업이 화면을 덮는다. 아래 일반 팁 「공지 팝업」대로 모두 닫는다.
- 메인 상단 메뉴: [나이스] [K-에듀파인] [센클라우드] [센메일] [기록관리시스템] … [교데통]
- 세션 타이머 존재(60분, 우측 상단에 "NN:NN후에 로그아웃됩니다" 표시).

### 4단계: [나이스] 클릭 → 새 탭으로 나이스 진입 (SSO 자동)

- 상단 좌측 **[나이스]** 텍스트 메뉴를 요소 찾기로 ref를 잡아 누르거나, 최신 스크린샷으로 위치를 확인해
  클릭한다. 창 폭에 따라 메뉴가 줄바꿈되므로 고정 좌표를 쓰지 않는다.
- **새 탭**이 같은 탭 그룹에 생성된다 (`sen.neis.go.kr/jsp/main.jsp`, 제목 "4세대 나이스 시스템").
  클릭 후 `wait 3초` → 탭 목록 조회로 새 탭 ID를 확보하고, 이후 조작은 새 탭 ID로 전환.
- **나이스는 별도 로그인 불필요** — 업무포털 세션으로 SSO 자동 로그인된다.

### 5단계: 나이스 메인 — 팝업 닫기, 화면 구조

- 나이스 메인에도 공지사항 팝업이 뜬다. 하단 **[닫기]** 로 모두 닫는다(일반 팁 「공지 팝업」).
- 화면 구조:
  - 상단: 학교명·사용자명, 세션 타이머(60분, "59분 NN초"), 로그아웃/튜토리얼/사용자지원 버튼
  - 상단 권한 탭: 사용자가 부여받은 권한별 탭 (예: 교과담임, 담임, 동아리담임, 부서 업무 등)
  - 좌측: 승인사항 + 기본 메뉴 (권한관리, 복무, 인사, 급여, 연말정산, 호봉, 연수,
    청렴마일리지, 원격업무지원서비스, 외부활동, 교원능력개발평가, 연계현황)
  - 중앙: 월간일정 / 학교일지·전달사항 / 업무요청내역

### 나이스 화면 조작 일반 팁

- **커스텀 드롭다운**: 나이스 콤보박스는 DIV 기반이라 폼 값 설정이 실패한다
  ("Element type DIV is not a supported form input"). 드롭다운을 클릭해 열고 → 스크린샷으로
  옵션 위치 확인 → 옵션을 클릭하는 방식으로 조작한다.
  `document.querySelectorAll('select')`가 빈 배열이면 커스텀 드롭다운이라는 확증이다.
  **옵션이 많은 드롭다운(시·분 등)은 현재값 주변만 보이므로, 열린 리스트 안에서 휠 스크롤로
  목표값을 화면에 들인 뒤 확대 캡처로 확인하고 클릭**할 것. 좌표만 믿고 누르면 옆 값이 잡힌다.
  드롭다운이 열리지 않고 화면만 그대로면 한 번 더 클릭한다.
- **커스텀 체크박스**: 그리드의 체크박스도 `input[type=checkbox]`가 아니어서
  페이지 JS 실행의 DOM 조회로 잡히지 않는다. 체크 상태 확인은 스크린샷 육안 검증으로.
- **날짜 입력**: 타이핑하지 않는다. 필드 유형은 셋이다.
  - **날짜 단독 필드**: 타이핑하면 원래 값으로 되돌아가거나 일부만 반영돼 `2-07-01`처럼 깨지고
    달력을 열면 연도가 `0002`로 뜬다(`ctrl+a` → `Delete` → 재입력도 같다. 포커스를 잃으면 원래
    값으로 돌아가 데이터는 상하지 않는다). **달력 아이콘 클릭 → 헤더 좌우 화살표(◀/▶)로 월 이동
    → 날짜 클릭**. ◀ 한 번이 1개월이고, 연 단위로 멀리 가려면 헤더(연월)를 눌러 연 단위로 넘긴다.
    기간 옆에 [오늘] [일주일] [1개월] [3개월] 같은 프리셋 버튼이 있으면 그것이 먼저다.
  - **날짜+시각 한 칸(eXBuilder6 DateInput)**: `year-month-day hours:minutes` 마스크라 문자열을
    치면 세그먼트가 어긋나 깨지고, JS로 `value`를 넣으면 즉시 원복된다. 확인된 유일한 절차:
    1. **달력 아이콘 클릭 → 날짜 클릭** → `YYYY-MM-DD 01:00`이 들어간다(시각은 항상 01:00).
    2. 입력란을 클릭하면 **연도 세그먼트가 선택**된다. `Right` ×3 → `Left` 로 **시(hour) 세그먼트**로 이동
       (Right 3번만으로는 분 쪽으로 넘어가므로 Left 한 번이 필요하다).
    3. `Up`/`Down` 으로 시를 증감(01 → 10이면 Up ×9), `Right` 로 분 세그먼트 이동 후 다시 `Up` ×N.
       키 입력에 반복 횟수를 줄 수 있으면 `Up` ×30도 한 번에 보낸다.
    4. 값 검증은 JS로 그 input의 `aria-label`을 찾아 `value`를 읽는다.
  - **연-월 달력**(급여지급월 등): 달력에서 월을 한 번 클릭하면 입력된다. 세그먼트 조작이 필요 없다.
- **학생부 텍스트 그리드 편집**(동아리 특기사항·독서활동·교과 세특 공통): 그리드가 CDP 합성
  이벤트에 예민해 아래 순서를 지킨다. 한도 Byte·빈 셀 기본값·성명 클릭 시 열리는 화면은 업무 파일에 있다.
  1. **셀을 클릭만 하면 편집되지 않는다.** 행이 하이라이트돼 편집 가능해 보여도 `type`이 통째로
     무시되고 Byte가 그대로다(에러가 없어 성공으로 오인하기 쉽다). 대상 셀 **더블클릭** → 2~3초 대기
     → **캐럿(커서) 확인**(확대 캡처. 커서가 없으면 더블클릭 재시도, 첫 더블클릭은 자주 빗나간다).
  2. 캐럿을 확인한 뒤 **별도 호출로 `type`**. 더블클릭과 같은 배치에 넣으면 에디터가 뜨기 전에
     발사돼 유실된다.
  3. **Byte 수와 본문을 함께 검증**한다. 한글 3Byte·그 외 1Byte로 기대값을 계산해 대조하면
     타이핑 누락·중복이 바로 잡힌다(ASCII 문자열은 글자 수 = Byte 수). 편집 중인 칸은
     `textarea`/`input`으로 렌더링되므로 JS로 `value`를 읽어 원고와 완전 일치 비교할 수 있다.
     Byte 표시가 커밋 뒤에야 갱신되는 화면(교과 세특 등)이 있으니, `value`가 맞는데 Byte가 그대로면
     4번 커밋 뒤에 다시 본다.
  4. **커밋**: 다음 학생 셀로 넘어가거나 저장·스크롤하기 전에 **중립 셀(반/번호·학적변동구분 등)을
     클릭**해 편집을 닫는다. 이전 셀 편집이 열린 채 다음 셀을 더블클릭하면 이전 셀 내용이 딸려
     들어오고(공유 에디터 오버레이), 편집 중에 스크롤하면 뷰포트가 편집 셀로 되돌아가 좌표가 틀어진다.
     **성명 셀은 누르지 않는다**(화면마다 다른 조회 팝업이 열린다).
  5. **저장 전 데이터는 클라이언트에만 있다.** 탭이 사라지면 입력분 전체가 유실되므로 여러 명을
     넣을 때는 **2~3명마다 [저장]**한다. → 사례
  6. **최종 검증은 [조회] 재실행** 후 그 행의 Byte와 본문이 그대로인지 본다(클라이언트 잔상과
     구분되는 유일한 지점).
- **입력 유실은 이 시스템의 상수다**: 행추가·드롭다운 선택처럼 그리드를 다시 그리는 조작
  **직후의 첫 타이핑은 자주 통째로 사라진다**(에러가 없어 성공으로 오인). 조작과 타이핑을
  **별도 호출로 분리**하고, 넣은 값은 매번 확인해 비었으면 한 번 더 넣는다.
  같은 조작을 두 번째로 하면 대체로 들어간다.
- **입력값 검증 — 폼은 JS, 편집 그리드는 확대 캡처**:
  - **폼 화면(신청 다이얼로그 등)**: 입력은 대부분 `aria-label` 이 한글 항목명으로 붙어 있다.
    `document.querySelectorAll('input,textarea')` 를 돌며 `aria-label → value` 맵을 만들고
    기대값과 `OK/DIFF`로 찍으면 폼 전체를 한 번에 대조할 수 있다.
    **CDP 한글 타이핑이 드물게 한 글자를 망가뜨리므로** 저장 전 기대값과 **완전 일치 비교**를 할 것.
    스크린샷 육안으로는 잡기 어렵다. → 사례
  - **편집 그리드는 편집 중인 셀만 `<input>`으로 렌더링한다**: `querySelectorAll('input')`이
    다른 행의 값을 돌려주지 않으므로, 여러 행을 한 번에 대조하려면 확대 캡처 스크린샷을 쓴다.
- **eXBuilder6 컴포넌트는 JS로 `value` 를 못 바꾼다**: 화면 프레임워크가 값을 자체 모델로
  관리해, 네이티브 setter + `input`/`change` 이벤트로 넣어도 즉시 원복된다. 값 변경은
  반드시 실제 클릭·키 입력으로 하고, JS는 **읽기(검증) 전용**으로 쓴다.
- **그리드 스크롤**: 순서는 이렇다.
  1. **읽기만 하면 되는 목록은 스크롤하지 말고 페이지 JS 실행으로 DOM에서 일괄 추출**한다
     (상신함 등은 가상 스크롤이 아니어서 화면 밖 행도 DOM에 있다). 스크린샷 왕복이 줄고
     텍스트도 정확하다. 단, 커스텀 체크박스처럼 DOM에 안 잡히는 요소는 여전히 육안 검증.
  2. 편집 그리드는 마우스 휠이 한 번에 몇 행밖에 안 움직이므로 우측 스크롤바 썸을
     `left_click_drag`로 끌어 큰 폭으로 이동하고, 미세 조정만 휠로 한다.
  3. 휠이 페이지를 움직이거나 썸만 움직이고 행이 갱신되지 않으면, 그리드 세로 스크롤 컨테이너
     (`div.cl-scrollbar` 중 `scrollHeight`가 큰 것)의 `scrollTop`을 JS로 넣고 `scroll` 이벤트를
     디스패치한다. 즉시 그 위치가 그려진다. 목표 행 위치는 `(번호−1)/전체인원 × scrollHeight`로
     어림잡고 스크린샷으로 확인한다.
     ```js
     const d=[...document.querySelectorAll('div.cl-scrollbar')]
       .filter(x=>x.scrollHeight>x.clientHeight+200).pop();
     d.scrollTop=850; d.dispatchEvent(new Event('scroll'));
     ```
     화면 밖 행 요소는 `getBoundingClientRect()`가 0이라 `scrollIntoView`도 통하지 않는다.
     창 크기 조정으로 창을 키워도 뷰포트가 그대로인 경우가 있어 행을 더 보려고 화면을 키우는 데
     기대지 말 것. → 사례
- **확인·완료 다이얼로그**: 나이스의 확인 창("저장하시겠습니까?" 등)과 완료 알림은 **클릭 후
  3~15초 늦게 뜬다.** 화면이 그대로면 대기 → 재스크린샷을 2회 반복한 뒤에야 실패로 판단한다.
  알림이 뜨기 전에 다른 버튼을 누르면 그 클릭이 알림에 먹혀 무시된다. → 사례
  버튼은 이 순서로 누른다.
  1. 최신 스크린샷 좌표로 클릭. 뜬 직후 위치가 한 번 옮겨지는 창은 JS로 보이는 `확인` 요소의
     `getBoundingClientRect()` 중심을 구해 아래 「좌표 환산」으로 바꿔 누른다.
  2. 좌표가 안 먹으면 JS로 보이는 요소 중 `textContent.trim()==='확인'`인 버튼을 찾아 `click()`.
  3. 요소 찾기 ref는 버튼 이름(확인/취소)이 드러날 때만 쓴다. 이름 없는 ref는 확인/취소 구분이 불확실하다.
  다이얼로그가 떠 있을 때는 Enter도 통하지만, 너무 일찍 치면 페이지로 샌다.
- **좌표 환산**: 접근성 트리 읽기의 viewport와 스크린샷 해상도가 다를 수 있다. 클릭 좌표는 항상
  스크린샷 픽셀 기준으로 잡는다. JS로 얻은 `getBoundingClientRect()` 좌표는
  **비율 = 스크린샷 폭 / `window.innerWidth`**를 그때마다 계산해 곱한다. 비율은 세션·창마다
  달라지므로 예전에 쓴 값을 재사용하지 않는다. → 사례
- **확대 캡처 타임아웃(중요)**: 확대 캡처는 뷰포트를 임시로 축소했다가 되돌리는데(Claude in Chrome에서 실측), 캡처가 타임아웃되면
  **뷰포트가 축소된 채 고착**될 수 있다(`window.innerWidth` 가 확대 캡처 영역 크기). 이후 스크린샷이
  계속 작게 나오거나 타임아웃되고 좌표 클릭이 어긋난다. 복구 순서:
  1. 먼저 창 크기 조정으로 복구를 시도한다.
  2. 안 되면 탭을 닫고 새 탭으로 다시 진입한다. 입력 중이었다면 탭을 닫기 전에 저장할 수 있는
     상태인지부터 확인한다(저장 전 입력분은 탭과 함께 사라진다).
  고착 중의 검증은 JS(`value` 읽기)로 한다. 같은 이유로 JS로 읽을 수 있는 폼 값은 JS로 검증하고,
  확대 캡처는 JS로 볼 수 없는 것(캐럿, 드롭다운 표시값·옵션 위치, 편집 그리드의 다른 행, 캔버스
  리포트, 커스텀 체크박스 등)을 확인할 때 쓴다. → 사례
- **iframe 안의 요소에는 요소 찾기/접근성 트리 읽기가 닿지 않는다**: 접근성 트리가 iframe 내부로
  내려가지 않아 ref를 얻을 수 없다. 파일 업로더처럼 iframe으로 구현된 위젯은
  최상위 문서에 임시 요소를 만들어 다리를 놓는 방식으로 우회한다
  ([references/외부강의-신고.md](references/외부강의-신고.md) 7번).
- **스크롤하면 좌표가 통째로 밀린다**: 화면 내용을 확인하려고 스크롤한 뒤 스크롤 전 좌표로
  버튼을 누르면 조용히 빗나간다(에러가 없어 "클릭이 씹혔다"로 오해하기 쉽다). 특히 **리포트
  뷰어 툴바처럼 페이지 중간에 있는 컨트롤**이 그렇다. 스크롤한 배치 다음에는 반드시 새
  스크린샷으로 좌표를 다시 잡는다.
- **공지 팝업은 여러 겹이다**: 업무포털과 나이스 모두 로그인 직후 공지가 뜨는데 **하나를 닫으면
  다음 공지가 이어서 뜬다**. 팝업 하단의 닫기(×)·[닫기]로 닫고, 닫은 뒤 반드시 스크린샷으로 재확인하고,
  남아 있으면 계속 닫는다. 팝업 [닫기]가 화면 밖이면 팝업 안에서 스크롤해야 보인다.
  "오늘 하루 보지 않기"는 사용자 선호를 확인하기 전까지 체크하지 않는다. → 사례
- **팝업 위로는 뒤 화면의 드롭다운을 조작할 수 없다**: 옵션 목록이 팝업 위에 그려져도
  클릭이 뒤 화면에 닿지 않는다. 조회 조건을 바꾸려면 팝업을 먼저 [닫기].
- **[닫기]를 눌러도 팝업이 남아 있을 수 있다**: 다음 조작 전에 스크린샷으로 실제로
  닫혔는지 확인한다(닫힌 줄 알고 좌표를 클릭하면 엉뚱한 곳이 눌린다).
- **탭·조회 버튼의 첫 클릭은 화면 로딩 중이면 씹힌다**: 반응이 없으면 2~3초 뒤 다시 누른다.
- **하단 탭바**: 열어본 화면들이 하단에 탭으로 쌓인다 (초기화면 / 정기시험채점 / …).
  탭 클릭으로 화면 간 전환 가능.
- **브라우저 제어 확장 공통 함정**(Claude in Chrome에서 실측):
  - **확장 창이 포그라운드가 아니면 `Page.captureScreenshot`이 30초 타임아웃**을 낸다
    ("The renderer may be frozen") — 페이지가 멈춘 것이 아니다. 사용자가 다른 크롬 창을
    쓰고 있으면 계속 재현되므로, **스크린샷 대신 페이지 텍스트 추출·페이지 JS 실행으로 판독**한다
  - **페이지 JS 실행 결과에 `location.href`가 섞이면 응답 전체가
    `[BLOCKED: Cookie/query string data]`로 차단**된다. URL·쿠키는 빼고 필요한 필드만 반환할 것.
  - **Chrome 팝업 창이 떴는지 `Get-Process chrome | MainWindowTitle`로 확인하면 안 된다** —
    MainWindowTitle은 프로세스당 하나만 돌려주므로 같은 프로세스의 새 창이 보이지 않는다.
    `EnumWindows`로 `Chrome_WidgetWin_1` 클래스 창 제목을 열거해야 한다. → 사례
  - **모든 탭에서 `Cannot attach to this target`이면 확장을 버리고 Playwright로 돌아간다**
    → [references/playwright.md](references/playwright.md).

## 일반 원칙

- 조회·판독 조작은 한 번에 묶어 실행한다(이동 → 대기 → 캡처 패턴. Playwright는 `run_code` 하나,
  확장은 일괄 실행).
  단 다음은 **단독 호출**로 한다: 그리드·폼을 다시 그리는 조작(행추가·드롭다운 선택·더블클릭·
  달력 날짜 선택) 뒤의 입력, 같은 배치에서 이어지는 두 번째 달력 조작, 주소 이동 재시도.
- 클릭 전 반드시 최신 스크린샷으로 좌표를 확인. 팝업이 화면을 덮고 있으면 먼저 닫는다.
- 인증서 비밀번호·개인 자격증명 입력은 절대 자동화하지 않는다. 로그인은 사용자 몫.

  세션이 끊기면(확장의 탭 그룹이 닫혀 탭 목록 조회가 실패할 때 포함)

  - **나이스 자체 인증서 로그인 화면**이 나오면 업무포털을 거치지 않고 그 화면에서 사용자가
    [인증서 로그인]을 한다.
  - 업무포털 세션까지 끊겨 업무포털이 로그인 페이지로 돌아가 있으면 2단계부터 다시 한다.
- **상신 전 사용자 확인(두 번)**: 상신은 되돌리기 어려운 대외 행위다([회수]·[기결취소]는 가능하지만

  - **확인 ①** 폼을 다 채운 뒤 **[승인요청]을 누르기 전**: 기간·시간대·사유·목적지·금액·여비 등
    입력 내용(+ 해당되면 잔여시간)을 요약해 확인받는다.
  - **확인 ②** [승인요청] 뒤 결재선을 조립한 다음 **[상신]을 누르기 전**: 결재선 그리드와 기안내용 표를
    요약해 확인받는다.
