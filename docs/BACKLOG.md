# 성능 개선 백로그

## 착수 순서

| 묶음 | 항목 | 필요 환경 | 순서 |
|---|---|---|---|
| 자료 조회 | **알림장 날짜 조회** | 로컬 필요 | 선행 |
| 자료 조회 | **쿨메신저 메시지 검색** | 로컬 필요 | 알림장 뒤 |
| 화면 조회 | **컴시간 학급 전환 대기** | 로컬 필요 | 실시간 조회 가능 시 |

학교 Windows 데스크톱에서 공개 저장소를 pull해 이 목록을 확인한다. 구현과 검증은 평소 실행하는 비공개 스킬 정본에서 진행하고, 검증한 변경만 다음 반출 때 공개본에 반영한다.

아래 수치는 Mac에서 합성 자료로 시험한 결과다. Windows에서는 같은 입력 사본으로 변경 전후 명령을 번갈아 여러 번 실행하고, 출력과 실행 시간 중앙값을 비교한다. PowerShell의 `Measure-Command`로 충분하다. Fast Anything은 함수별 시간을 다시 조사할 때만 사용한다.

## 작업 항목

- [ ] **알림장 날짜 조회**. `alim_export.py`의 `source_for`는 날짜 범위를 확인하면서 부서별 메모 본문도 읽는다. 후보 폴더의 범위를 확인할 때는 날짜만 해석하고, 범위가 겹치는 보관 폴더에서는 기존처럼 본문이 있는 날짜 수로 고른다. 합성 자료에서는 이전 학년도 하루 조회가 55.7ms에서 40.2ms로 줄었다. 현재 학년도, 범위가 겹치는 이전 학년도, 기록이 없는 날짜에서 선택한 폴더·출력·종료 코드를 대조한다. 자동 선택을 검증할 때는 이를 건너뛰는 `--src` 옵션을 생략한다.
- [ ] **쿨메신저 메시지 검색**. `cm_export.py`에서 보낸 사람과 검색어로 SQLite에서 먼저 걸러 읽는 방법을 검토한다. 합성 메시지 10만 건에서 보낸 사람 검색은 253ms에서 63ms, 제목·본문 검색은 251ms에서 104ms로 줄었다. 전체 내보내기는 차이가 작았다. 받은 쪽지와 보낸 쪽지의 CSV·JSON 내용과 순서를 대조한다. 단순 필터는 바이너리 본문이나 깨진 UTF-8 행을 건너뛰어 기존 오류를 성공으로 바꿀 수 있다. 이 사례까지 회귀 테스트로 확인한 뒤 적용한다.
- [ ] **컴시간 학급 전환 대기**. `comci.py`의 `fetch`에서 같은 주 30학급 조회에 지정된 고정 대기는 합계 13초다. 실제 단축 시간은 미측정이다. 브라우저에서 학급이나 주를 바꿀 때 선택한 학급·날짜와 표 본문이 모두 갱신되는 시점을 확인한다. 이전 학급 표를 읽는 일이 없는지 검증한 대기부터 줄인다.
