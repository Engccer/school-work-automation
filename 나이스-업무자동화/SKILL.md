# 나이스 업무 자동화 (업무포털 → 나이스 진입)

## 개요

서울특별시교육청 업무포털을 거쳐 4세대 나이스에 진입하는 브라우저 자동화 워크플로우.
Claude in Chrome MCP 도구를 사용한다. **인증서 로그인은 반드시 사용자(교사 본인)가 직접 수행**한다
(인증서 비밀번호 입력은 자동화 금지 영역).

- 업무포털: `https://sen.eduptl.kr/bpm_man_mn00_001.do` (메인) / `bpm_lgn_lg00_001.do` (로그인)
- 나이스: `https://sen.neis.go.kr/jsp/main.jsp` (업무포털에서 SSO로 진입)

> **적용 범위**: 서울특별시교육청 환경(`sen.*` 도메인)에서 실사용으로 검증했다. 타 시도는
> 업무포털·나이스 서브도메인이 다르지만 4세대 나이스 화면 구조는 전국 공통이라 절차 골격은
> 그대로 적용된다.

## 사전 점검 (브라우저 연결)

1. ToolSearch로 Chrome 도구를 **한 번에** 로드:
   `select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__find,mcp__claude-in-chrome__browser_batch,mcp__claude-in-chrome__list_connected_browsers`
2. `list_connected_browsers`로 연결 확인. `[]`(빈 배열)이면:
   - Chrome 실행 + Claude 확장 로그인 상태 확인을 사용자에게 요청
   - **연결에 시간이 걸릴 수 있음.** 사용자가 "확인해 봐"라고 할 때 재시도하면 잡히는 경우가 많다.
     (실측: 첫 요청 시 수 분간 `[]`였다가 이후 연결됨)
3. `tabs_context_mcp {createIfEmpty:true}` → 새 창+새 탭이 생성된다. 이 탭 ID로 이후 모든 조작을 수행.

## 워크플로우

### 1단계: 업무포털 접속 → 로그인 페이지

- `navigate` → `https://sen.eduptl.kr/bpm_man_mn00_001.do`
- 미로그인 상태면 자동으로 `bpm_lgn_lg00_001.do` (로그인 페이지)로 리다이렉트된다.
- **주의(시행착오)**: navigate 직후 스크린샷은 흰 화면일 수 있다. `wait 2~3초` 후 스크린샷을 찍을 것.

### 2단계: 세션 공유 안 됨 — 사용자 로그인 대기

- **핵심 시행착오**: 사용자가 다른 탭/창에서 이미 업무포털에 로그인해 있어도,
  자동화 탭에서 `main.html` 등으로 직접 접근하면 **"해당 서비스 호출에 실패하였습니다"** 오류가 뜬다.
  이 포털은 로그인 절차를 거친 탭(창)에서만 세션이 유효하다. 기존 로그인 세션에 편승할 수 없다.
- 따라서 자동화 탭을 로그인 페이지(`bpm_lgn_lg00_001.do`)에 둔 상태로 사용자에게 요청:
  **"교육행정 전자서명 인증서 로그인" 버튼을 눌러 인증서 로그인을 직접 진행해 주세요.**
- 사용자가 이 탭에서 로그인하면 기존 탭 세션이 끊길 수 있음을 미리 안내한다(중복 로그인 제한 가능).
- 로그인 완료 통보를 받으면 `tabs_context_mcp` + 스크린샷으로 확인.
  성공 시 탭 제목 "업무포털 메인", URL `bpm_man_mn00_001.do`.

### 3단계: 업무포털 메인 — 공지 팝업 닫기

- 로그인 직후 KERIS 등 공지 팝업이 화면을 덮는다. 팝업 하단의 **닫기(×)** 를 클릭해 닫는다.
  ("오늘 하루 이창 보지 않기" 체크는 하지 않는다 — 사용자 선호 확인 전까지)
- 팝업이 여러 개일 수 있으니 닫은 뒤 스크린샷으로 재확인.
- 메인 상단 메뉴: [나이스] [K-에듀파인] [센클라우드] [센메일] [기록관리시스템] … [교데통]
- 세션 타이머 존재(60분, 우측 상단에 "NN:NN후에 로그아웃됩니다" 표시).

### 4단계: [나이스] 클릭 → 새 탭으로 나이스 진입 (SSO 자동)

- 상단 좌측 **[나이스]** 텍스트 메뉴 클릭 (좌표 예: 1568px 폭 기준 약 (320, 68)).
- **새 탭**이 같은 탭 그룹에 생성된다 (`sen.neis.go.kr/jsp/main.jsp`, 제목 "4세대 나이스 시스템").
  클릭 후 `wait 3초` → `tabs_context_mcp`로 새 탭 ID를 확보하고, 이후 조작은 새 탭 ID로 전환.
- **나이스는 별도 로그인 불필요** — 업무포털 세션으로 SSO 자동 로그인된다.

### 5단계: 나이스 메인 — 팝업 닫기, 화면 구조

- 나이스 메인에도 공지사항 팝업이 뜬다. 하단 **[닫기]** 버튼 클릭.
- 화면 구조:
  - 상단: 학교명·사용자명, 세션 타이머(60분, "59분 NN초"), 로그아웃/튜토리얼/사용자지원 버튼
  - 상단 권한 탭: 사용자가 부여받은 권한별 탭 (예: 교과담임, 담임, 동아리담임, 부서 업무 등)
  - 좌측: 승인사항 + 기본 메뉴 (권한관리, 복무, 인사, 급여, 연말정산, 호봉, 연수,
    청렴마일리지, 원격업무지원서비스, 외부활동, 교원능력개발평가, 연계현황)
  - 중앙: 월간일정 / 학교일지·전달사항 / 업무요청내역

## 업무별 워크플로우

### 정기고사 OMR 일괄채점 (2026-07-06 기말고사에서 정립)

교무부 안내 기준 절차: OMR 리딩·업로드 완료 후 교과담임이 나이스에서 일괄채점.

1. **메뉴**: 상단 권한 탭 **교과담임** → 좌측 **정기시험** → **정기시험채점**
   (좌측 메뉴 구성: 문항정보표관리 / 정기시험학생답관리 / 정기시험채점 / 정기시험성적관리)
2. **조회 조건**: 학년도·학기·고사(기말고사)·학년·과목 설정 후 [조회].
   - 담당 과목이 하나면 고사 선택 시 과목이 자동 채워진다.
   - 조회 결과: 좌측에 강의실(반) 목록 + 반별 대상자 수가 표시된다.
3. **서답형 점수 소스 선택**: "학생답안 선택형 +" 드롭다운에서 **성적관리 서답형** 선택.
   - 옵션: 학생답안 서답형 / 성적관리 서답형 / 직전성적관리 서답형
   - **시행착오**: 이 선택이 화면 재렌더링으로 "선택"으로 되돌아가는 경우가 있다.
     선택 후 zoom으로 표시값을 확인하고, 리셋됐으면 다시 선택할 것.
4. **강의실 전체 체크**: 목록 헤더의 전체선택 체크박스 클릭 → 담당 반이 모두 체크됐는지 확인.
5. **[일괄채점]** 클릭 → 확인 다이얼로그("선택한 반(들)에 대해서 일괄채점 하시겠습니까?") → [확인].
   - **시행착오(중요)**: 나이스 다이얼로그는 클릭 후 즉시 스크린샷에 안 잡힐 수 있다.
     화면이 안 변한 것처럼 보여도 3~5초 대기 후 재스크린샷하면 다이얼로그가 나타난다.
     결과 알림("N 강의실 N건의 채점이 수행되었습니다" 반별 목록)도 지연 표시되므로,
     채점 후 다른 조작 전에 반드시 대기+재스크린샷으로 알림을 확인하고 [확인]으로 닫을 것.
6. **검증**: 알림의 반별 채점 건수가 조회된 대상자 수와 일치하는지 대조.
   각 강의실 행을 클릭하면 우측에 "최종 채점일 : YYYY.MM.DD. HH:MM:SS"가 표시된다 (채점 전엔 "미채점").
   채점 완료 후 체크박스·드롭다운은 자동 리셋된다.
7. **주의**: 채점 후 정답 오류 등 문제 발견 시 임의 재채점 금지 — 반드시 평가계 문의 (교무부 지침).

### 정기고사 문항별 정답률·학년 통계 조회 (2026-08-12 정립)

교과협의록의 "문항분석"("○번, ○번 문항을 제외하고는 정답률 60% 이상" 류 서술)이나
난이도 점검에 쓸 **문항 단위 정답률**과 **학년 단위 성적 통계**를 뽑는 절차. 조회 전용이며
채점 화면은 건드리지 않는다.

1. **메뉴**: 상단 권한 탭 **교과담임** → 드롭다운 **성적 > 정기시험조회/통계** →
   좌측 **정기시험통계**. (같은 묶음의 **정기시험조회**는 일람표·결시생·학생답 정오표 등
   원자료 화면이고, 통계 리포트는 전부 **정기시험통계** 쪽에 있다)
2. **정기시험통계 화면은 상단 탭 5개**이고, 탭마다 조회 조건이 다르다. **강의실(반) 조건이
   있는지가 곧 "반 단위냐 학년 단위냐"** 를 가른다.

   | 탭 | 조회 조건 | 산출물 | 단위 |
   |----|----------|--------|------|
   | 도수분포표 | 학년도·학기·고사·학년·과목 + **급간** | 급간별 인원(반별 열 + 합계), 응시자·결시자, **반별 평균** | 학년 |
   | 구간비교표 | …·학년 + **N점 이상 ~ M점 미만** | 그 구간에 드는 인원을 **교과목 × 반**으로, 하단에 과목별 인원·합계·평균 | 학년(전 교과) |
   | 정답률비교표 | …·학년·과목 | **문항번호 × 반 정답률 + 평균 열**, 마지막 행에 반별 총평균 | 학년 |
   | 문항분석표 | …·학년·과목 + **강의실** | 문항별 **답지별 반응분포**(반 인원(학년 전체 인원)), 정답, **정답률 "반(학년전체)"**, 무표기 | 반(+학년 값 병기) |
   | 성적집계표 | 학년도·학기·과정·고사·학년 (과목 없음) | **교과목 × 반 평균**, 응시자·결시자, 최고점·최하점(전입생 제외), 과목평균 | 학년(전 교과) |

3. **문항별 정답률은 두 곳에서 나오고 값이 미묘하게 다르다.**
   - **정답률비교표의 "평균" 열 = 반별 정답률의 단순평균**(반 인원 차이 미반영).
   - **문항분석표 정답률의 괄호 값 = 학년 전체 응시자 기준 정답률**. 학년 전체를 말하려면
     이쪽이 정확하다. 단 강의실이 필수 조건이라 **아무 반이나 하나 조회하면 괄호 값이 곧
     학년 전체 값**이므로 반을 7번 돌 필요가 없다.
   - 검산: 문항별 정답률의 평균이 협의록에 쓴 **선택형 득점률과 일치**하면 판독이 맞다는
     방증이 된다(실측: 25문항 평균 77.9% = 선택형 득점률 77.9%).
4. **서답형 문항별 정답률은 없다.** 두 리포트 모두 **선택형 문항까지만** 실린다
   (답지번호 1~5 구조라 서답형은 애초에 표에 들어가지 않는다). 서답형은 영역 단위 득점률·
   0점/만점 인원으로 서술할 수밖에 없다. 문항 단위가 꼭 필요하면 정기시험조회 >
   **교과목별학생답정오표**(학생 × 문항 정오)에서 직접 집계해야 한다.
5. **변별도 지표는 제공되지 않는다.** "문항분석표"라는 이름과 달리 내용은 답지 반응분포 +
   정답률 + 무표기이고, 변별도(상·하위 집단 정답률 차)는 어느 탭에도 없다.
6. **표준편차도 없다.** 학년 단위 통계 3종(도수분포표·구간비교표·성적집계표) 어디에도
   표준편차 열이 없으므로, 협의록에 표준편차를 쓰려면 개인 점수에서 직접 계산해야 한다.
   대신 급간별 인원(도수분포표)과 구간 인원(구간비교표)으로 분포는 충분히 서술된다.
7. **리포트는 전부 팝업 뷰어 + 캔버스 렌더링**이다. iframe 안이 `canvas` 1개라
   `javascript_tool`로 텍스트를 못 걷는다(`body.innerText`가 "/ 2 100%"뿐).
   **스크린샷 + `zoom`으로 읽는 것이 유일한 경로**이며, 다음을 따르면 왕복이 줄어든다.
   - 로딩이 **10~18초**로 길다. "로딩 중입니다" 화면에서 성급히 조작하지 말 것.
   - 페이지 이동은 뷰어 상단 `≫ ＜ ＞ ≪` 버튼. 한 페이지가 화면보다 길면 **캔버스 위 휠
     스크롤은 먹지 않고**, 우측 스크롤바 썸을 `left_click_drag`로 끌어야 한다.
   - 페이지 경계에서 문항이 끊긴다(실측: 1페이지 1~16, 2페이지 17~25). **2페이지에서

5. **검증 방법**: 학년 열 헤더의 괄호 숫자(예: "1학년 (14)")가 **체크된 교시 수 = 등록된
   이수시간 합계**다. 이 숫자를 운영계획표의 시수 합계와 대조하면 스크롤 없이 총량을
   검증할 수 있다. 상세 검증은 스크롤하며 체크된 일자·교시를 운영계획과 대조.
6. 변경했다면 [저장] 클릭. 이미 등록된 상태라면 아무 조작 없이 종료(임의 재저장 불필요).

### 상신함에서 결재 완료 내역 추출 (2026-08-10 정립)

"계획이 아니라 **실제로 결재된 날**을 확인해야 하는" 업무(복무 결과보고, 출장 정산,
근무시간면제 사용 실적 등)의 근거 자료를 상신함에서 뽑는 절차. 계획 문서와 대조하면
계획 대비 실제 사용의 차이를 그대로 잡아낼 수 있다.

1. **메뉴**: 나이스 좌측 최상단 **승인사항 > 상신함**. (권한 탭과 무관하게 항상 노출)
2. **조회 조건**: 업무영역 / 결재문서 / 결재문서명 / **상신기간**(필수) / 진행상태.
   - **상신기간 기본값은 최근 1개월**이다. 학기·연 단위로 보려면 시작일을 넓혀야 한다.
   - **기간 필드 오른쪽에 [오늘] [일주일] [1개월] [3개월] 프리셋 버튼이 있다.**
     클릭 한 번으로 시작일이 그만큼 앞당겨지므로(종료일은 오늘 유지), **3개월 이내
     범위라면 달력을 열 필요가 전혀 없다.** 달력 화살표 조작보다 훨씬 빠르고 안전하니
     먼저 프리셋으로 커버되는지 확인하고, 그보다 긴 기간만 아래 달력 방식을 쓴다.
   - **날짜 필드에 직접 타이핑하지 말 것.** 클릭 후 타이핑하면 일부 글자만 반영돼
     `2-07-01` 같은 깨진 값이 되고, 달력을 열면 **연도가 `0002`** 로 뜬다.
     (`ctrl+a` → `Delete` → 재입력도 동일하게 깨진다. 포커스를 잃으면 원래 값으로
     되돌아가므로 데이터가 상하진 않는다.)
     → **달력 아이콘 클릭 → 헤더 좌우 화살표(◀/▶)로 월 이동 → 날짜 클릭**이 유일하게 안전한 방법.
     ◀ 한 번이 1개월이므로, 7월에서 3월로 가려면 4번 클릭한다.
   - **결재문서명은 일반 텍스트 입력이라 한글 타이핑이 정상 동작한다.** 문서 종류
     이름 일부(예: 특정 복무 유형명)를 넣고 [조회]하면 그 유형만 남길 수 있다 —
     수십~수백 건에서 대상만 추리는 가장 빠른 방법.
   - **진행상태 라디오**: 전체 / 진행중 / 기결 / 반려 / 기결취소. 기본값 "전체"로 조회한
     뒤 행별 진행상황 열을 직접 확인하는 편이 안전하다. **"완결"과 "기결취소"를 반드시
     구분할 것** — 취소된 신청을 실적에 넣으면 허위 보고가 된다.
3. **행 데이터 일괄 추출**: 이 그리드는 **가상 스크롤이 아니다.** "50개씩 보기"에서
   Total이 50 이하면 전체 행이 DOM에 렌더링되므로 `javascript_tool`로 한 번에 걷을 수 있다.
   (스크린샷으로 한 화면씩 읽지 말 것)

   ```js
   // 리프 노드에서 문서명을 찾고, 조상으로 거슬러 올라가 행 전체 텍스트를 얻는다
   const els=[...document.querySelectorAll('div,span,td')]
     .filter(e=>e.children.length===0 && /<문서명 패턴>/.test(e.textContent));
   els.map(e=>{let p=e;
     for(let i=0;i<6;i++){p=p.parentElement; if(!p)break;
       const t=p.innerText||''; if(/완결|기결|반려|진행/.test(t)) return t.replace(/\s+/g,' ').trim();}
   });
   ```
   - **행 전체 텍스트를 그대로 반환하면 출력이 잘린다.** 정규식으로 **필요한 필드만**
     (기간·진행상황 등) 뽑아 배열로 만들고 `JSON.stringify`할 것.
   - 문서명이 같은 행이 중복 수집될 수 있으므로 키(예: 시작일시)로 `Set` 중복 제거.
4. **누락 검증**: 조회 시작일을 더 이른 날짜로 넓혀 재조회했을 때 **Total이 그대로면**
   그 구간에 누락이 없다는 뜻이다. 필터를 상위 개념(예: 문서 대분류명)으로 바꿔
   유형별 건수를 집계하면 다른 유형으로 처리된 건이 있는지도 함께 확인할 수 있다.
   유형별 건수의 합이 Total과 일치하면 전 행이 DOM에 있다는 방증도 된다.
5. **취소 문서 주의**: 결재 취소는 `[기결취소기안]<원문서명>` 형태의 **별도 행**으로
   상신함에 남는다. 취소 대상이 무엇인지 문서명에서 확인할 것.

   - 결재상태 드롭다운(전체/…)으로 진행 단계별 필터도 가능.
3. **목록 열**: 순번 / 관할교육청 / 소속 / 직급 / 성명 / 기간 / 요청기관명 /
   외부강의시간 / 외부강의금액 / 결재상태. `Total N`이 연간 신고 건수다.
   - 톱니바퀴 > **컬럼 설정**으로 확인해도 **숨은 열은 없다** — 이 목록에는
     강의 주제·장소가 아예 없으므로, 상세는 아래 4번 경로로 봐야 한다.
4. **상세 확인 경로**: **승인사항 > 상신함 → 결재문서명 `외부강의신고` 링크 클릭 →
   "상신함 상세보기"**. 여기서 두 가지를 한 번에 얻는다.
   - **결재선 표**: 기안자·검토자·결재자별 승인 일시까지 나오므로 "언제 완결됐는지"가 확정된다.
   - **상신내용**: 상세보기 하단에 **인라인으로 이미 표시된다**(우측 [팝업] 버튼은
     같은 내용을 별도 창으로 크게 띄우는 용도이므로 굳이 누르지 않아도 된다).
     필드: 신고자/소속/직급, 장소, 일시, 강의시간, 실비(여비), 월(연)평균횟수,
     강사료(원고료포함), 원고료, 1회 평균시간, 총액, 요청 기관명·부서·담당자,
     연락처, 공문번호, 요청서류 [첨부파일].
   - **주의**: 상신내용에도 **강의 주제(제목) 필드는 없다.** 주제까지 대조하려면
     로컬에 보관한 신고서 원본(hwpx/md)을 함께 읽을 것.
5. **시행착오(중요) — 완결 건은 목록 체크박스가 아예 안 눌린다.**
   행 체크박스를 클릭해도 체크되지 않고, 그 상태로 [외부강의신고서]를 누르면
   "선택된 외부강의 신고내역이(가) 없습니다" 알림이 뜬다. 행을 더블클릭하면 사유가
   나온다 — **"업무승인 진행중이거나 완결된 신고는 삭제등의 작업이 불가하여 체크가
   되지않습니다"**. CDP 합성 클릭 실패로 오해해 좌표를 바꿔가며 반복하지 말 것.
   `find`로 ref를 잡아 눌러도 동일하다. 즉 **완결 건은 [외부강의신고서]·[삭제] 불가**이고,
   신고서 출력이 필요하면 로컬 원본이나 K-에듀파인 결재 문서를 쓴다.
   - 이 알림들도 **4~5초 지연 렌더링**이라, 클릭 후 화면이 그대로여도 대기 후 재스크린샷할 것.
   - 성명 열 링크도 완결 건에서는 상세가 열리지 않는다(무반응).
6. **신고 대상 여부 먼저 판단할 것(중요)**: 강의를 나갔다고 모두 신고 대상이 아니다.
   **교육부·교육청 및 그 직속기관이 의뢰한 강의는 신고 불필요**하다
   (시·도 특수교육원, 교육연수원, 교육지원청 등이 여기 해당. 청탁금지법상
   국가·지방자치단체 요청에 따른 외부강의등은 신고 예외).
   신고가 필요한 것은 대학·산학협력단, 학회·협회, 기업, 출판사 등 **외부 기관 의뢰** 건이다.
7. **누락 점검**: 상신함을 같은 기간으로 조회해 **강사·강의 사유의 출장/복무 건과
   외부강의 신고 건수를 대조**하면, 강의를 나갔는데 신고가 빠진 건을 잡아낼 수 있다.
   - 단, 대조 결과를 "누락"으로 단정하지 말 것. 출장 사유에 "강사"가 있어도 위 6번의
     교육청 직속기관 의뢰 건이면 신고 자체가 불필요하다. **의뢰 기관이 어디인지
     확인한 뒤**, 신고 대상으로 보이는데 신고가 없는 건만 사실로 제시한다.
     (실측: 특수교육원 의뢰 강의를 "신고 누락 가능성"으로 잘못 보고한 사례가 있다)

### 외부강의 신고 등록·상신 (2026-08-12 정립)

접수된 강의 요청 공문을 근거로 외부강의등 신고를 새로 등록하고 결재에 올리는 절차.
**신고 대상인지 위 「현황 조회」 6번으로 먼저 판단**한 뒤 진행한다.

1. **메뉴**: 기본 메뉴 > 외부활동 > **외부강의등록**. 로딩이 끝나 기간이 당해 1/1~12/31로
   채워지면 [조회]로 **연간 기존 신고 목록을 먼저 확인**한다(중복 등록 방지). 그다음 **[등록]**.
2. **화면 상단 안내문을 반드시 읽을 것.** 실무 판단이 여기 다 적혀 있다 —
   여비(교통비·식비·일비·숙박비)는 실비란, **원고료는 강사료에 포함**(2015.09~),
   **외부강의 기간이 한 달 이상이면 겸직허가 대상**, **강의시간은 1시간 단위로만 입력 가능**,
   공직유관단체 지정 국가기관·지자체의 사례금 지급 건도 신고 대상.
3. **입력 필드**: 일시(시작~종료, 분 단위) / 장소 / 강의주제 / 강의시간 / 강사료(원고료포함) /
   실비(여비) / 원고료 / 일괄신고 체크 / 요청비고 / 요청자(기관명·부서·담당자·연락처) /
   공문번호 / [첨부파일]. 총액·월(연)평균횟수·1회 평균시간은 자동 계산(readonly).
   - **공문번호는 요청 기관의 시행 문서번호**(예: `○○과-1532`)를 쓴다. 학교 접수번호가 아니다.
   - 강의시간은 공문상 시간(예: 10:30~12:30 → 2)으로 맞춘다. 실제 진행 시간이 조정됐더라도
     신고서는 공문 기준으로 쓰고, 그 차이는 로컬 기록에 남긴다.
4. **일시 필드(eXBuilder6 DateInput)가 이 화면 최대 난관 — 타이핑 금지.**
   `year-month-day hours:minutes` 마스크 입력이라 문자열을 그대로 치면
   `2-08-14 01:30`처럼 세그먼트가 어긋나 깨진다. `ctrl+a`+Delete 후 숫자만 쳐도 깨지고,
   **JS로 `value`를 넣으면 컴포넌트가 즉시 원복**시킨다(완전 제어형 입력).
   확인된 유일한 안전 절차:
   1. **달력 아이콘 클릭 → 날짜 클릭** → `YYYY-MM-DD 01:00`이 들어간다(시각은 항상 01:00).
   2. 입력란을 클릭하면 **연도 세그먼트가 선택**된다. `Right` ×3 → `Left` 로 **시(hour) 세그먼트**로 이동.
      (Right 3번만으로는 분 쪽으로 넘어가므로 Left 한 번이 필요하다)
   3. `Up`/`Down` 으로 시를 증감(01 → 10이면 Up ×9), `Right` 로 분 세그먼트 이동 후 다시 `Up` ×N.
   4. `computer` 액션의 `repeat` 를 쓰면 `Up` ×30도 한 번에 보낸다.
   5. 값 검증은 **JS로 `aria-label`이 `강의시작일`/`강의종료일`인 input의 value를 읽어** 확인한다
      (`zoom` 스크린샷보다 정확하고 빠르다).
5. **텍스트·숫자 필드는 일반 입력이라 클릭 후 타이핑이 정상 동작**한다. 숫자칸(0이 들어있는
   강의시간·강사료 등)은 `triple_click` 으로 선택한 뒤 타이핑하면 덮어써진다.
   금액은 `220,000` 처럼 콤마가 자동으로 붙고, 총액이 즉시 재계산되는지로 반영을 확인한다.
6. **입력 후에는 반드시 JS로 전 필드 일괄 대조**할 것. `aria-label` → 기대값 맵을 만들어
   `OK/DIFF` 로 찍으면 한 번에 검증된다. **CDP 한글 타이핑은 드물게 한 글자를 망가뜨린다**
   (실측: `워크숍` → `워크숨`). 스크린샷 육안으로는 잡기 어렵다.
   - 고쳐 넣을 때 `triple_click` → `ctrl+a` → `Delete` 는 **씹혀서 기존 값 뒤에 덧붙는 사고**가 난다.
     `left_click` → 2초 대기 → `ctrl+a` → 1초 → `BackSpace` 순서로 비운 뒤 다시 입력한다.
7. **첨부파일(RaonK 업로더) — 네이티브 파일 대화상자로는 못 넣는다(중요).**
   [첨부파일] → "감사파일첨부" 모달이 뜨고, 그 안은 **`iframe[id^=raonkuploader_frame]`** 이다.
   [파일 추가]를 누르면 Chrome 네이티브 "열기" 창(#32770)이 열리는데,
   **PowerShell로 파일명 Edit에 `WM_SETTEXT` 후 열기 버튼을 눌러도 렌더러에 파일이 전달되지 않는다**
   (`input.files.length` 가 계속 0. `BM_CLICK`·`WM_COMMAND`·실제 Enter 키 모두 실패).
   - **네이티브 창은 페이지 스크린샷에 안 잡힌다.** 화면이 멀쩡해 보여도 대화상자가 떠 있을 수 있고,
     [파일 추가]를 반복해서 누르면 **창이 쌓인다**(한 번에 하나만 보이므로 눈치채기 어렵다).
     따라서 **[파일 추가]는 되도록 누르지 말고**, 눌렀다면 아래 명령으로 잔여 창이 0인지
     확인·정리한 뒤 다음 단계로 넘어갈 것. 방치하면 사용자가 나중에 그 창을 마주친다(실측).
     ```powershell
     # 보이는 #32770 중 제목이 '열기'인 창 열거 → 남아 있으면 PostMessage WM_COMMAND IDCANCEL(2)
     ```
   대신 다음 경로가 확실하다(**[파일 추가]를 아예 누르지 않는다**).
   1. JS로 **최상위 문서에 임시 `<input type=file>`** 을 만들고 화면에 보이게 스타일을 준 뒤
      `aria-label` 을 붙인다(`find` 가 잡을 수 있게).
   2. `find` 로 그 임시 input의 ref를 얻어 **`file_upload` 도구로 실제 파일을 넣는다.**
      (a11y 트리는 **iframe 내부로 내려가지 않아** 업로더의 진짜 input에는 ref를 못 붙인다)
   3. JS로 임시 input의 `File` 객체를 꺼내 **iframe 실행 컨텍스트의 `DataTransfer`** 에 담고
      `uploaderInput.files = dt.files` 로 대입한 뒤 `change` 이벤트를 디스패치한다.
      ```js
      const f = document.querySelector('iframe[id^=raonkuploader_frame]');
      const w = f.contentWindow, d = f.contentDocument;
      const inp = d.querySelector('input[type=file]');
      const dt = new w.DataTransfer(); dt.items.add(srcInput.files[0]);
      inp.files = dt.files; inp.dispatchEvent(new w.Event('change', {bubbles:true}));
      ```
   4. 목록에 `1 개, NN KB 추가됨` 이 뜨는지 확인하고 **임시 input을 지운다.**
   5. **[선택]** 클릭 → *"파일첨부는 완료되었습니다. 첨부파일이 전달되는 화면에서 저장하셔야
      최종 저장됩니다."* → [확인]. 즉 **여기서 끝이 아니라 신고 화면의 [저장]까지 눌러야** 첨부가 남는다.
   - 업로더의 진짜 input은 부모 DIV가 `display:none` 이라 크기가 0×0이다. 잘못 넣었으면
     [전체 파일제거]로 비우고 다시 넣으면 된다.
8. **[저장]** → "저장이 완료되었습니다." → 목록에 `결재상태 미상신` 으로 행이 생긴다.
   여기까지는 되돌릴 수 있는 상태이므로, **사용자에게 내용을 요약해 확인받고 상신으로 넘어간다.**
9. **상신**: 목록에서 해당 행 **체크** → **[승인요청]** → 기안문서상신 화면.
   결재문서명은 `외부강의신고 - <학교>_<직급>_<성명>` 으로 자동 생성된다.
10. **결재선은 [개인결재선]보다 [결재자지정]이 확실하다(중요).**
    개인 결재선 팝업은 **행을 클릭해도 우측 패널이 갱신되지 않거나 직전/다른 행의 결재선을
    보여준다.** 같은 행을 두 번 눌러야 뜨기도 하고, 팝업을 닫았다 열어도 재현이 일정하지 않다.
    → 어떤 결재선이 잡혔는지 신뢰할 수 없으므로, 결재선을 **[결재자지정]에서 직접 조립**한다.
    1. 팝업 우측 상단 **구분 라디오(결재/검토/협조/공람)를 먼저 고른다** — 이후 추가하는
       사람의 구분이 된다.
    2. `사용자명` 에 이름을 넣고 [조회] → 행 체크 → **[▼]** 로 아래 결재선 그리드에 추가.
    3. 검토자를 다 넣은 뒤 라디오를 **결재**로 바꾸고 최종 결재자를 추가한다.
    4. **[저장]** 을 누르면 기안문서상신 화면의 결재선 그리드에 그대로 반영된다
       (이 [저장]은 개인 결재선을 새로 만드는 것이 아니라 현재 기안에 적용하는 동작).
    - **직전 같은 유형 문서의 결재선을 그대로 재현하는 것이 가장 안전하다.**
      승인사항 > 상신함에서 결재문서명으로 필터 → 완결 건 상세보기 → 결재선 표에
      `결재순번/구분/사용자ID/사용자명/직위` 가 다 나온다. 그 구성을 그대로 만든다.
11. **[상신]** → "상신하겠습니까?" [확인] → "상신을 완료하였습니다." [확인].
    **두 다이얼로그 모두 8~15초 지연**되므로, 화면이 그대로여도 기다렸다가 재스크린샷할 것.
12. **검증**: 외부강의목록의 결재상태가 `상신(진행)` 으로 바뀐다. 상신함을 재조회하면
    (한 번에 안 뜨면 [조회]를 한 번 더) 새 행이 잡히고, 상세보기에서
    결재선·상신내용·요청서류 [첨부파일] 목록(`1 개, NN KB`)까지 최종 확인할 수 있다.

### 근무상황 신청 — 육아시간·근무시간면제 등 (2026-08-11 정립)

복무를 신청해 결재에 올리는 절차. 하루 단건도, 같은 시간대를 여러 날 반복하는 건
(육아시간·모성보호시간 등)도 같은 화면에서 처리한다.

1. **이전 신청 내용부터 확보할 것.** "지난번과 똑같이 올려 줘"가 대부분이므로,
   먼저 **승인사항 > 상신함**에서 결재문서명에 근무상황 유형명(예: 해당 휴가명)을 넣어
   조회하고, 최근 **완결** 건의 문서명 링크로 상세보기를 연다. 여기서 재사용할 값이
   한 화면에 다 나온다 — 결재선(승인 일시 포함), 상신내용의 기간 표기
   `YYYY-MM-DD HH:MM ~ YYYY-MM-DD HH:MM (N일 매 시간 N분)`, 사유, 연락처, 대상 자녀 등.
   - **"완결"과 "기결취소"를 반드시 구분**할 것. 취소된 건을 원본으로 삼으면 안 된다.
2. **메뉴**: 기본 메뉴 > **복무 > 개인근무상황관리**. 조회 기간 기본값은 당월 1일~말일.
   (하위에 `육아시간신청조회`·`육아시간실적조회`가 따로 있지만 **신청 자체는 개인근무상황관리**에서 한다)
3. **[신청]** 클릭 → "근무상황신청" 다이얼로그. **기본 행 1개(연가)가 자동 생성되는 경우와,
   목록이 `Total 0` "데이터를 조회해 주십시오"로 비어 있는 경우가 둘 다 있다.** 비어 있으면
   **[행추가]** 를 눌러야 기본 행이 생긴다(누르기 전에는 하단 폼이 비활성처럼 보인다).
   행이 생기면 하단 "근무상황신청입력" 폼이 그 행과 실시간 연동돼, 폼을 고치면 위 목록 행이
   즉시 갱신된다. [행추가]를 더 누르는 것은 성격이 다른 건을 한 번에 올릴 때만.
   - 기존 건을 그대로 복제하려면 목록에서 대상 행을 선택하고 **[복사]** 버튼을 쓰는 경로도 있다.
4. **근무상황 분류**: 대분류(연가/병가/공가/특별휴가/대체휴무/결근/연수/기타) → 소분류.
   대분류를 바꾸면 소분류가 첫 항목으로 자동 세팅되지만, **소분류 드롭다운을 열어 항목을
   클릭해 확정**해야 하위 필드와 사용현황 표가 제대로 채워진다.
   - **육아시간·모성보호시간 → 특별휴가 하위**. 확정하면 자녀명 필드가 활성화된다.
   - **근무시간면제(노동조합 타임오프) → 기타 하위**. 확정하면
     *"근무시간 면제자로 지정된 사람만 면제시간을 사용할 수 있습니다"* 알림이 뜬다(정상, [확인]).
   - 소분류 확정 시 위쪽 "근무상황사용현황" 표가 그 유형 전용으로 바뀐다. 근무시간면제는
     **면제기간별 부여시간 / 사용시간 / 잔여시간(`0200:00` 형식)** 이 나오므로,
     신청 전에 **잔여시간이 이번 신청 시간을 감당하는지 확인하고 사용자에게 함께 보고**할 것.
5. **드롭다운은 전부 커스텀 DIV** — `document.querySelectorAll('select')`가 **빈 배열**이라
   `form_input` 불가. 클릭해서 열고 → 스크린샷으로 옵션 위치 확인 → 옵션 클릭.
   - **시/분 드롭다운은 현재값 근처만 보인다.** 목표값이 화면 밖이면 **열린 리스트 안에서
     휠 스크롤**로 이동해야 한다(기본 16시에서 08시로 가려면 위로 여러 번). 스크롤 후
     `zoom`으로 값을 확인하고 클릭할 것 — 좌표만 믿고 누르면 옆 값이 잡힌다.
6. **날짜는 달력 아이콘으로만.** 시작 → 종료 순서로 설정한다.
   - **시작일자를 바꾸면 종료일자가 같은 날로 동기화**되므로 종료일을 먼저 잡으면 헛수고다.
   - 시작일 선택 직후 **같은 배치에서 종료일 달력을 열면 씹힌다**(동기화 렌더링과 충돌).
     별도 호출로 달력 아이콘을 다시 클릭할 것.
7. **하루 단건**은 반복 체크가 필요 없다. 시작·종료 일자를 같은 날로 두고 시각만 바꾸면
   신청시간이 `0일 N시간 0분`으로 자동 계산된다(예: 12:30~16:30 → `0일 4시간 0분`).
   전일(예: 08:30~16:30)은 `1일 0시간 0분`으로 잡힌다.
8. **여러 날 같은 시간대 = [일반복] 체크(핵심).** 시작일시·종료일시를 **하루치 시간대**
   (예: 시작일 08:30 ~ 종료일 08:50)로 맞춘 뒤 **일반복**을 체크하면 신청시간이
   `N일 매 0시간 20분`으로 자동 계산된다. 체크 전에는 기간 전체를 한 덩어리로 계산해
   일수가 0으로 나온다. 특정 요일만 쓸 때는 [요일반복] + 요일 체크박스.
   - 위 목록 행의 `반복 / 일 / 시간 / 분` 열이 `매 / 3 / 0 / 20`처럼 바뀌는지로 검증.
9. **나머지 필드**(전부 일반 입력이라 클릭 후 타이핑이 정상 동작한다):
   - **연락처** — 숫자만 이어서 입력하면 마스크가 `(010)0000-0000`으로 자동 정형된다.
   - **사유** — 한글 타이핑 정상. 직전 완결 건의 문구를 그대로 재사용하는 것이 안전하다.
   - **목적지** — 사유 오른쪽 칸. 근무지를 벗어나는 복무(근무시간면제·출장 등)에서 채운다.
   - **자녀명** 드롭다운 — 육아시간 필수(선택하면 우측에 총 사용일수 표시).
   - **비공개여부** — 기간/목적지/사유에 체크하면 일일근무상황에 공개되지 않는다.
10. **[승인요청]** → **기안문서상신** 화면으로 전환. 결재문서명은 자동으로 채워지고
   하단 기안내용에 신청 건이 실린다. *"화면 하단의 기안내용이 정상적으로 초기화하면 상신
   버튼이 활성화됩니다"* 안내대로 **로딩 완료 전 클릭은 무시**되므로, [개인결재선]이
   무반응이면 3~5초 뒤 재클릭한다(첫 클릭이 먹지 않는 것이 정상).
11. **[개인결재선]** → "개인 결재선 지정" 팝업. 미리 저장해 둔 결재선 목록에서 용도에 맞는
    것을 클릭하면 우측에 결재순서·구분(검토/결재)·결재자가 표시된다. **결재자와 순서를
    사용자가 지정한 라인과 대조**한 뒤 [지정]. 결재선 그리드에 기안자(0번) 아래로
    검토·결재자가 붙는다.
    - 용도별 결재선(연수용, 출장·연가용, 부서 업무용, 육아시간용 등)을 미리 만들어 두면
      매번 결재자를 검색할 필요가 없다. 없으면 [결재자지정]으로 직접 고른다.
    - **시행착오: 팝업의 행 하이라이트와 실제로 로드되는 결재선이 어긋난다.** 4번 행을 눌렀는데
      2번 결재선이 패널에 뜨는 식이다(더블클릭해도 동일). **결재선명이 아니라 우측 패널에
      표시된 결재자 목록을 보고 판단**할 것 — 실측상 [지정] 결과는 패널 내용과 일치했다.
      반복 클릭으로 씨름하지 말고 [지정]한 뒤 **기안문서상신 화면의 결재선 그리드에서
      최종 확인**한다. 여기가 진짜 검증 지점이고 아직 [상신] 전이라 다시 지정하면 된다.
    - **저장된 결재선과 원하는 조합이 다를 때**: 가장 가까운 결재선을 [지정]한 뒤,
      **기안문서상신 결재선 그리드에서 뺄 결재자 행을 체크하고 [삭제]** 하면 된다.
      결재순서는 자동 재부여된다(기안 0 → 검토 1 → 결재 2). 결재선을 새로 만들 필요 없다.
      - **[삭제] 알림도 지연 렌더링(5~10초)이다.** 알림이 뜨기 전에 [상신]을 누르면
        그 클릭이 알림에 먹혀 무시된다. "삭제하였습니다"를 닫은 뒤 [상신]할 것.
12. **[상신]** → "상신하겠습니까?" → [확인] → "상신을 완료하였습니다." → [확인].
    이 다이얼로그들은 좌표 클릭이 통한다(안 되면 find ref). **[상신] 직후 화면이 그대로여도
    정상** — 확인 창이 5~10초 뒤에 뜨므로 대기 후 재스크린샷할 것.
13. **검증**: 다이얼로그가 닫히면 개인근무상황관리 목록이 자동 갱신된다. 새 행의
    근무상황·기간·`일수/기간`(예: `3일매 시간20분`, `0일4시간0분`)·사유·목적지·
    **결재상태(상신(진행))**를 확인한다. 화면 하단 총계도 함께 갱신된다.
14. **상신은 되돌리기 어려운 대외 행위**다. 폼을 다 채운 뒤 **기간·시간대·사유·목적지·결재선
    (+ 해당되면 잔여시간)을 사용자에게 요약해 확인받고** [승인요청]을 누를 것.
    (회수는 [회수] 버튼, 결재 완료 후 취소는 [기결취소]로 가능하지만 상대 결재자에게 흔적이 남는다)
15. **잘못 올린 건 되돌리기 — [회수] vs [기결취소](중요).** 두 버튼은 대상이 다르다.
    - **아직 아무도 결재하지 않았으면 [회수]** 다. 상신함에서 진행상황 `상신(진행)`이고
      **현처리자가 첫 검토자**면 이 경우다. 상신함이든 개인근무상황관리든 대상 행을
      체크하고 [회수] → "선택한 N건을 회수하겠습니까?" → [확인] → "회수하였습니다."
      (확인 창·완료 알림 모두 5~10초 지연. 목록은 자동 갱신되지 않으니 [조회]로 다시 읽을 것)
    - 결재가 끝난(완결) 건을 되돌리는 것이 **[기결취소]** 이고, 이때는 `[기결취소기안]…`
      문서가 상신함에 별도로 남는다.
    - 회수 후 상태: 상신함 진행상황 `기결취소`, 개인근무상황관리 결재상태 `상신취소`.
      **근무상황 행 자체는 목록에 남는다**(삭제 아님).
16. **회수한 건을 같은 내용으로 다시 올리기 — [복사]가 정답.** 개인근무상황관리에서
    `상신취소` 행을 체크하고 **[복사]** → "근무상황신청수정" 다이얼로그가 열리면서
    **분류·기간·시각·연락처·사유·목적지가 전부 그대로 복사**된다. 바꿀 것만 고치고
    [승인요청] → (필요하면 결재선 조정) → [상신]. 값을 다시 입력할 필요가 없다.
    - **주의: [복사]는 새 행을 만든다.** 원래 `상신취소` 행이 목록에 남아 화면 하단
      **총계(일수/기간)에 계속 합산**되므로(실측: 4시간이 중복 계상), 정리하려면 그 행을
      체크하고 [삭제]한다. 결재 이력은 상신함에 남으므로 감사 근거는 사라지지 않는다.
    - **`상신취소` 행 삭제 절차**: 같은 기간·같은 유형의 행이 나란히 있으므로
      **체크 직후 `결재상태` 열을 `zoom`으로 확대해 `상신취소` 행만 잡혔는지 확인**한 뒤
      [삭제]한다. "삭제하시겠습니까?" → [확인] → 해당 행이 분홍색으로 바뀌고,
      **다시 5~10초 뒤** "삭제가 완료되었습니다" 알림이 뜬다. 알림을 닫아도 목록은
      그대로이니 **[조회]로 재조회**해야 행이 사라지고 총계가 정정된다.
17. **세션 타이머 주의**: 신청 다이얼로그 안에서만 오래 조작하면 상단 타이머가 계속 줄어든다
    (폼 입력은 세션 갱신으로 치지 않는 듯). 화면 전환이 일어나면 60분으로 리셋된다.
    저장 전 입력값은 만료 시 전량 소실되므로, 남은 시간이 10분 안쪽이면 서두르거나
    [승인요청]까지 먼저 넘겨 화면을 전환시킬 것.
    - **MCP 탭 그룹이 닫히면 나이스 세션도 끊긴다.** `tabs_context_mcp`가
      "No tab group exists"를 반환하면 새 탭에서 `sen.neis.go.kr/jsp/main.jsp`로 바로
      이동해 볼 수 있으나, 세션이 죽었으면 **나이스 자체 인증서 로그인 화면**이 나온다.
      이 경우 업무포털을 거칠 필요 없이 그 화면에서 사용자가 [인증서 로그인]을 하면 된다.

### 출장 신청 — 개인출장관리 (2026-08-12 정립)

출장은 **복무 > 개인근무상황관리가 아니라 복무 > `개인출장관리`** 에서 신청한다.
근무상황 신청과 화면 구조가 비슷하지만 출장자 목록(동반자)과 여비 항목이 따로 있다.

1. **여비지급 여부부터 판단할 것(가장 중요).**
   **강사료·원고료·수당·자문료 등 사례금이 지급되는 출장(외부 강의, 자문·심의 회의 등)은
   학교 결재에서 무조건 여비 부지급**으로 올린다. 요청 기관이 사례금을 지급하므로 학교
   예산에서 여비를 이중으로 받지 않는다는 취지다. 접수 공문에 강사료·수당 표기가 있으면
   그것이 곧 부지급 근거이며, 사용자에게 되묻기 전에 부지급을 기본값으로 잡는다.
   - 반대로 사례금이 없는 협의회·연수·인솔 출장 등은 여비 지급이 기본이다.
   - `여비지급하지않음` 체크 시 *"여비부지급의 경우 에듀파인으로 연계되지 않습니다"*
     알림이 뜨는데 **정상**이다([확인]).
   - **검증 지점은 [승인요청] 후 기안내용 표의 `여비지급여부` 열**이다. `지급안함`이면 맞다
     (지급이면 `지급안함` 대신 `지급`). 상신 전 반드시 이 열을 확인할 것.
2. **선례 확보**: 승인사항 > 상신함에서 결재문서명에 `출장`을 넣고 조회하면 과거 출장 신청이
   모두 나온다. 문서명이 `출장신청-[국내출장(관내)]기간:…` 형태라 관내/관외가 바로 구분되고,
   완결 건 상세보기에서 결재선과 상신내용(출장인원·여비지급여부·여비지급기관)을 그대로 볼 수 있다.
   **관내와 관외는 결재권자가 다를 수 있으므로 같은 출장종류의 선례**를 볼 것.
3. **[신청]** → "출장신청" 다이얼로그. 기간정보 행 1개가 자동 생성된다(당일 08:30~16:30).
   - **출장종류를 먼저 확정**한다(국내출장(관내) / 국내출장(관외) / 국외출장 / 출장(연수)).
     화면 안내대로 **출장(연수)는 출장비가 지급되지 않는다.**
   - 날짜는 **달력 아이콘**으로만. 시작일을 바꾸면 종료일이 동기화되므로 시작 → 종료 순서.
   - 시·분은 커스텀 드롭다운이라 목표값이 화면 밖이면 **열린 리스트 안에서 휠 스크롤** 후 클릭.
     반영되면 신청시간이 `0일 3시간 20분`처럼 자동 계산된다.
4. **필수 텍스트 필드**(클릭 후 타이핑 정상): 연락처(숫자만 치면 `010-0000-0000`으로 정형),
   출장지, 출장목적. 이동사항은 선택. 저장 전 `aria-label → value` JS 대조로 한글 깨짐을 점검한다.
5. **동반자(출장자 목록)**: [추가] → "출장자 선택" 팝업에서 성명으로 조회 → 행 체크 → [추가].
   - **동명이인이 흔하다.** 목록에 `성명(사용자ID)`로 표시되고 직급 열이 비어 있을 수 있으므로,

   - 추가된 행은 `출장기간동일여부 = Y`로 대표자와 같은 기간이 적용된다. 그리드 가로 스크롤로
     종료 시각까지 눈으로 확인할 것.
6. **[승인요청]** → 기안문서상신 → 결재선 지정 → **[상신]** → "상신하겠습니까?" → 완료 알림.

   동반자가 있으면 `○○○ 외 N 명`으로 표기된다. 상신함 상세보기에서 결재선·여비지급여부까지 확인.

### 나이스 화면 조작 일반 팁

- **커스텀 드롭다운**: 나이스 콤보박스는 DIV 기반이라 `form_input`이 실패한다
  ("Element type DIV is not a supported form input"). 드롭다운을 클릭해 열고 → 스크린샷으로
  옵션 위치 확인 → 옵션을 클릭하는 방식으로 조작한다.
  `document.querySelectorAll('select')`가 빈 배열이면 커스텀 드롭다운이라는 확증이다.
  **옵션이 많은 드롭다운(시·분 등)은 현재값 주변만 보이므로, 열린 리스트 안에서 휠 스크롤로
  목표값을 화면에 들인 뒤 `zoom`으로 확인하고 클릭**할 것.
- **커스텀 체크박스**: 그리드의 체크박스도 `input[type=checkbox]`가 아니어서
  javascript_tool의 DOM 조회로 잡히지 않는다. 체크 상태 확인은 스크린샷 육안 검증으로.
- **그리드 스크롤**: 마우스 휠 스크롤은 한 번에 몇 행밖에 안 움직인다. 행이 많은 그리드는
  우측 스크롤바 썸을 `left_click_drag`로 끌어 큰 폭으로 이동하고, 미세 조정만 휠로 한다.
  단 **읽기만 하면 되는 목록은 스크롤하지 말고 `javascript_tool`로 DOM에서 일괄 추출**한다
  (상신함 등은 가상 스크롤이 아니어서 화면 밖 행도 DOM에 있다). 스크린샷 왕복이 줄고
  텍스트도 정확하다. 단, 커스텀 체크박스처럼 DOM에 안 잡히는 요소는 여전히 육안 검증.
- **날짜 입력 필드**: 타이핑 입력이 무시되고 원래 값으로 되돌아가는 필드가 있다.
  달력 아이콘 클릭 → 달력에서 날짜 선택 방식을 기본으로 할 것.
  **날짜+시각 한 칸짜리 필드(DateInput)** 는 달력으로 날짜만 잡히고 시각은 `01:00` 으로
  들어가므로, 세그먼트 이동(`Right`/`Left`) + `Up`/`Down` 으로 시·분을 맞춘다
  (「외부강의 신고 등록·상신」 4번 참조).
- **입력값 검증은 스크린샷보다 JS가 정확하다**: 이 화면들의 입력은 대부분 `aria-label` 이
  한글 항목명으로 붙어 있다. `document.querySelectorAll('input,textarea')` 를 돌며
  `aria-label → value` 맵을 만들면 폼 전체를 한 번에 대조할 수 있다.
  **CDP 한글 타이핑이 드물게 한 글자를 망가뜨리므로**(실측 `워크숍`→`워크숨`) 저장 전
  기대값과 **완전 일치 비교**를 할 것.
- **eXBuilder6 컴포넌트는 JS로 `value` 를 못 바꾼다**: 화면 프레임워크가 값을 자체 모델로
  관리해, 네이티브 setter + `input`/`change` 이벤트로 넣어도 즉시 원복된다. 값 변경은
  반드시 실제 클릭·키 입력으로 하고, JS는 **읽기(검증) 전용**으로 쓴다.
- **`zoom` 액션 타임아웃 주의(중요)**: `zoom` 은 뷰포트를 임시로 축소했다가 되돌리는데,
  캡처가 타임아웃되면 **뷰포트가 축소된 채 고착**된다(`window.innerWidth` 가 zoom 영역 크기,
  예: 182×25). 이 상태에서는 스크린샷이 계속 타임아웃되고 좌표 클릭도 불가능하며,
  `resize_window` 로도 복구되지 않는다. **탭을 닫고 새 탭으로 다시 진입하는 것이 유일한 복구**다.
  입력 도중 이런 일이 나면 저장 전 데이터가 날아가므로, 검증은 되도록 `zoom` 대신 위의 JS 방식을 쓴다.
- **iframe 안의 요소에는 `find`/`read_page` 가 닿지 않는다**: 접근성 트리가 iframe 내부로
  내려가지 않아 ref를 얻을 수 없다. 파일 업로더처럼 iframe으로 구현된 위젯은
  최상위 문서에 임시 요소를 만들어 다리를 놓는 방식으로 우회한다
  (「외부강의 신고 등록·상신」 7번 참조).
- **read_page 좌표 주의**: read_page의 viewport(예: 1920px)와 스크린샷 해상도(예: 1568px)가
  다를 수 있다. 클릭 좌표는 항상 스크린샷 픽셀 기준으로 잡을 것.
  JS로 얻은 `getBoundingClientRect()` 좌표도 같은 비율(예: ×0.817)로 환산해야 맞는다.
- **하단 탭바**: 열어본 화면들이 하단에 탭으로 쌓인다 (초기화면 / 정기시험채점 / …).
  탭 클릭으로 화면 간 전환 가능.

## 일반 원칙

- 여러 조작은 `browser_batch`로 묶어 한 번에 실행 (navigate → wait → screenshot 패턴).
- 클릭 전 반드시 최신 스크린샷으로 좌표를 확인. 팝업이 화면을 덮고 있으면 먼저 닫는다.
- 인증서 비밀번호·개인 자격증명 입력은 절대 자동화하지 않는다. 로그인은 사용자 몫.
- 세션 타이머(60분)가 있으므로 장시간 작업 시 만료에 유의. 만료 시 2단계부터 재수행.
- 성적 등 민감 데이터 화면에서는 스크린샷을 파일로 저장하지 않는다(`save_to_disk` 금지).
- **이 스킬 문서는 외부 공개를 전제로 한다.** 스킬을 갱신할 때 개인·학교 식별 정보를 기록하지
  않는다: 교사·학생 이름, 학교명, 담당 학년·반·과목, 반별 인원수, 계정 ID 등은 모두 일반화해서
  쓸 것 (예: "담당 반 목록이 표시된다").
