# e알리미 상벌점 자동화

> **적용 범위**: 상벌점V.2 메뉴를 쓰는 학교의 교사 계정에서 실사용으로 검증했다. 상벌점 항목과 배점은
> 학교마다 다르므로 고정하지 않고 화면에서 조회한다.

사용자가 결정한 상벌점을 화면에서 입력하고 결과를 확인한다. 행동에 대한 사실 판단이나 징계 결정을 대신하지 않는다.

## 공개 파일에 남기는 정보

이 스킬과 함께 배포하는 모든 파일에는 절차적 지침만 포함한다. 실제 이름, 학적 조합, 연락처, 계정·기관·학생·등록 건 식별자, 개인 경로, 인증정보, 실제 부여 사례와 화면 캡처를 저장하지 않는다. 실행 중 확인한 개인정보를 예시·주석·테스트 데이터·작업 로그로 복사하지 않는다. 학교별 항목 번호와 배점표도 고정하지 않고 해당 계정 화면에서 조회한다.

## 시작과 작업 범위

- 브라우저는 Playwright 브라우저 도구를 기본으로 쓰고 `https://www.ealimi.com/`에 접속한다. 로그인 화면이면 사용자에게 Playwright 창에서 로그인을 요청하고 같은 탭에서 이어 간다. 비밀번호를 스킬에 보관하지 않는다.
- 브라우저 제어 확장(Claude in Chrome에서 검증)은 개발자 도구가 막힌 크롬 프로필에서 페이지 읽기만 되고 클릭·JavaScript·캡처가 `Cannot attach to this target`으로 실패한다. 이 오류가 나면 재시도하지 말고 Playwright로 옮긴다. Playwright 창은 기존 크롬의 로그인 세션을 공유하지 않는다.
- 계정의 소속과 부여자를 확인한다. 홈 공지가 메뉴를 가리면 팝업의 닫기를 사용한다.
- 메뉴 **상벌점V.2 → 상점/벌점 부여**로 진입한다. 메뉴가 없으면 계정·권한을 확인하고 다른 계정으로 임의 전환하지 않는다.
- 사용자가 방법·항목 조회나 입력 준비만 요청했다면 등록하지 않는다. 대상·발생일·항목·점수·비고·알림 설정이 확정되고 등록을 요청했다면 같은 내용을 재승인받지 않고 진행한다.
- 항목이 불명확하면 실제 선택지와 배점을 보여 주고 사용자가 결정하게 한다. 비고의 행동 사실은 사용자가 제공한 내용만 쓴다.
- 알림은 등록과 별개로 대상과 방식을 확정한다. 알림을 요청하지 않았다면 발송 안 함을 유지한다. SMS와 앱 미설치자 SMS 대체 발송은 포인트 차감 선택지이므로 사용자의 비용 발생 허용 범위에서만 켠다.
- 입력을 시작하기 전에 목록에서 같은 대상·발생일·항목의 기존 기록을 조회한다. 특히 재요청이나 중단 후 재개는 이전 등록의 완료 여부부터 확인한다. 기존 기록과 별도 사건인지 불명확하면 등록 전에 확인한다. 조회가 끝난 뒤 입력 화면으로 이동해 미저장 내용을 잃지 않게 한다.

## 화면 경로

아래 경로는 메뉴를 찾는 단서다. 현재 계정의 화면과 링크를 확인하고 사용한다.

| 화면 | 경로 |
|---|---|
| 상벌점 홈 | `/PenaltyV2/Home` |
| 상점/벌점 목록 | `/PenaltyV2/Points` |
| 단건등록 | `/penaltyV2/PointsWrite` |
| 개별건 일괄등록 | `/penaltyV2/pointsWriteMulti` |
| 개인별 현황 | `/PenaltyV2/UserPenalty` |
| 부여내역 상세보기 | `/penaltyV2/PointsView` |

## 단건등록: 같은 항목을 한 명 또는 여러 명에게 부여

1. **대상자**에서 이름을 입력하고 Enter로 검색한다. 입력만으로 검색이 실행됐다고 보지 않는다. Enter 뒤에도 결과 목록이 뜨지 않을 수 있으니, 그때는 학년을 먼저 고르고 반으로 좁힌다.
2. 결과의 이름·학년·반·번호를 대조한 뒤 대상자 라벨을 선택한다. 선택 목록과 `N명 선택됨`을 확인한다. 같은 이름·학적의 결과가 여러 개면 첫 행을 임의 선택하지 않고 계정 구분에 필요한 정보를 확인한다. 전체선택은 검색 결과 전원이 요청 대상일 때만 쓴다. 검색 팝업은 **닫기**로 닫는다.
3. **부여자**가 현재 작업 계정인지 확인하고 **발생일**을 맞춘다. 초기 날짜가 오늘이어도 사용자가 말한 사건 발생일을 우선한다. 날짜는 현재 시간대 기준 도구로 확인한다. 날짜 필드의 직접 입력 가능 여부는 화면에서 확인하고 필요하면 달력을 이용한다.
4. **유형**에서 상점·상점차감·벌점·벌점차감 중 요청한 것을 고른다. 차감은 기존 기록 삭제와 다른 작업이므로 혼용하지 않는다.
5. **분류 → 항목 → 점수** 순서로 선택한다. 매 단계에서 다음 목록의 갱신을 확인한다. 항목 선택 뒤 점수와 알림 미리보기가 채워질 수 있다. 점수 선택지가 하나면 해당 항목의 고정 배점으로 안내하고, 여러 개면 요청 점수를 허용 범위 안에서 고른다. 원하는 점수를 만들기 위해 다른 항목을 임의 선택하지 않는다.
6. **비고**를 요청대로 채우거나 공란으로 둔다.
7. **메시지 발송**의 대상과 방식을 검증한다. 초기 화면은 학부모·학생·담임 미선택, **알림 발송 안함** 선택 상태였으나 실행마다 확인한다.
   - 알림 없음: 발송 안 함, 수신 대상 미선택, SMS 옵션 꺼짐을 확인한다.
   - 알림 있음: 요청한 학부모·학생·담임만 선택하고 푸시 또는 SMS 방식을 맞춘다. 발신번호와 미리보기 문구도 확인한다. 미리보기의 학적·이름 치환 표시는 템플릿이므로 임의로 실명으로 바꾸지 않는다.
8. 선택 인원과 대상, 발생일, 유형·분류·항목·점수, 비고, 알림 설정을 다시 읽는다. 확정된 요청과 일치하면 **등록을 한 번만** 누른다.

## 저장 결과와 중복 방지

- 단건등록의 성공 경로는 JavaScript 알림 **저장되었습니다. → 확인 → 상점/벌점 목록**이다. 알림이 열린 동안 DOM 조회나 캡처가 막힌다. Playwright에서는 등록 클릭 결과의 모달 상태에서 알림 문구를 읽고 대화상자 처리 도구로 수락해 닫으면 목록으로 이동한다.
- 목록 로딩이 끝나면 요청한 모든 대상·행을 찾아 학년·반·번호·이름, 유형, 분류, 항목, 점수, 등록자, 발생일을 대조한다. 여러 명을 선택한 단건등록과 개별건 일괄등록 모두 요청 건수와 확인 건수가 일치해야 전체 완료로 보고한다. 일부만 확인되면 성공·실패·미확인을 구분하고 전체를 다시 등록하지 않는다.
- 해당 행의 **항목 링크**를 열어 **부여내역 상세보기**에서 발생일·점수·비고를 확인한다. **부여일시**는 등록 시각이며 사건의 발생일과 구분한다. 알림 없음 요청은 **메시지 발송 이력**도 비어 있는지 확인한다.
- 저장 알림이나 화면 이동이 늦어도 등록을 다시 누르지 않는다. 먼저 목록에서 결과를 조회한다. 조회 후에도 성공·실패를 구분할 수 없으면 상태 미확인으로 보고하고 자동 재등록하지 않는다.
- 이미 같은 대상·날짜·항목의 기록이 있으면 기존 건인지 이번 건인지 등록 시각과 상세 내용으로 구분한다. 의도된 별도 사건 여부가 불명확하면 중복 부여 전에 확인한다.
- 완료 보고는 대상, 항목, 점수, 발생일, 비고·알림 상태를 간단히 정리한다. 실제 개인정보가 포함된 보고나 검증 화면은 공개 스킬 폴더에 저장하지 않는다.

## 여러 유형을 함께 입력할 때

**개별건 일괄등록 하기 > → + 새 행 추가**로 행을 만든다. 행마다 이름 검색, 학년·반·번호, 유형·분류·항목·점수, 발생일과 복사·삭제 컨트롤이 있다. 이름을 선택하기 전 학년·반·번호 선택기는 비활성 상태일 수 있다.

단건등록의 대상 확인 원칙을 각 행에 적용하고 행 수·중복을 확인한다. 이 화면의 알림 설정은 공통 영역에 있으므로 대상마다 다른 알림 설정이 필요하면 요청별로 나누어 처리한다. 행 복사는 학생·발생일 등도 함께 복제될 수 있으므로 복사 결과 전체를 확인한다.

일괄등록은 양식과 빈 행 구조까지 확인된 경로다. 실제 저장·복사 동작과 이름 선택 이후의 학적 설정은 단건등록과 같다고 단정하지 말고 현재 화면에서 검증한다. 행별 비고가 필요한데 입력란이 없으면 단건등록을 사용한다. 최초 실행은 사용자가 요청한 실제 건으로 검증하며 조사 목적으로 가짜 기록을 만들지 않는다.

## 목록에서 찾기

**상점/벌점 → 필터 및 검색**에는 발생일 범위, 유형, 분류·항목, 학년·반, 대상자 이름, 부여자 이름 조건이 있다. 검색 조건 패널의 **저장**과 신규등록 양식의 **등록**을 구분한다. 여러 유형이 함께 선택되어 있으면 분류·항목 선택기가 비활성일 수 있다.

- 발생일의 초기값은 오늘 하루다. 기존 기록과 누적을 보려면 학년도 라디오를 골라 범위를 넓힌 뒤 대상자 이름으로 **저장**한다. 결과가 여러 쪽이면 쪽수를 함께 보고한다.
- 이름 검색 결과에는 동명이인 기록이 섞일 수 있다. 행마다 학년·반·번호로 걸러 요청 대상의 기록만 집계하고, 다른 학생 기록을 중복 근거로 삼지 않는다.

상세 화면에는 수정·삭제·메시지 재발송이 있지만 이 스킬의 검증 목적은 조회다. 기존 기록 수정·삭제·재발송은 해당 요청과 현재 화면의 동작을 별도로 확인한 뒤 처리한다. 이들 작업의 완료 절차는 단건 신규등록으로 검증된 것이 아니다.

## UI 자동화 시 주의할 동작

- 유형 라디오의 입력 요소를 직접 클릭하거나 `check()` 하면 상태가 바뀌지 않는 경우가 있다. 인접한 정확한 텍스트 라벨을 클릭한 뒤 `checked` 상태를 읽는다. 학생 체크박스도 라벨 클릭 후 선택 인원으로 검증한다.
- 학년·반, 유형·분류·항목은 비동기로 갱신된다. 직후 읽은 목록이 직전 값이면 새 상태를 확인한 다음 진행한다. 고정 대기시간만으로 갱신 성공을 판정하지 않는다.
- 반 선택기의 DOM에는 다른 학년의 같은 이름 옵션이 숨겨진 채 남을 수 있다. 학년을 먼저 고르고 해당 학년에서 표시되는 반을 선택한 뒤 실제 검색 결과의 학년·반을 검증한다. Playwright `selectOption`에 반 이름만 주면 숨은 다른 학년 옵션이 잡힐 수 있으므로, `data-group1num`이 고른 학년과 같은 옵션의 index를 구해 `selectOption({ index })`로 고른다.
- 항목 후보를 찾을 때는 유형을 고른 뒤 분류를 하나씩 바꾸며 항목 목록을 모두 읽는다. 사용자의 행동 묘사와 같은 단어의 항목이 없으면 문구가 포괄하는 항목을 근거와 함께 제시하고 사용자가 고르게 한다.
- 선택기는 의미 있는 접근성 이름으로 찾는다. 단건등록의 주요 이름은 `대상자를 검색하세요.`, `1차 그룹 선택`, `2차 그룹 선택`, `발생일(필수)`, `분류 선택(필수)`, `항목 선택(필수)`, `점수 선택(필수)`, `비고`다. 학교별 식별자를 하드코딩하지 않는다.
- 현재 화면에 근거한 브라우저 상호작용으로 처리한다. 앱 내부 함수 호출이나 추정한 비공개 API로 저장을 우회하지 않는다.
