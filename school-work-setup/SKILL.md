# 학교 업무 자동화 설치 점검

번들의 일곱 스킬이 이 컴퓨터에서 바로 돌 수 있는지 점검한다. 읽기만 하고 아무것도 설치하지 않는다(크롬 원격 디버깅 시험만 임시 프로필로 화면 없는 크롬을 잠깐 띄웠다가 지운다). 설치는 사용자가 결과를 보고 고른다.

## 1. 쓸 스킬 고르기

사용자가 특정 업무만 말했으면 그 스킬만 점검한다("알림장만" → `alimjang-automation`). 말이 없으면 일곱 개 전부다.

| 업무 | 스킬 |
|---|---|
| 나이스 | `neis-automation` |
| K-에듀파인 | `k-edufine-automation` |
| 교데통 | `kyodetong-submit` |
| 쿨메신저 | `coolmessenger-automation` |
| 알림장 | `alimjang-automation` |
| e알리미 상벌점 | `ealimi-points` |
| 컴시간 시간표 | `comcigan-timetable` |

## 2. 점검 스크립트

스킬 루트에서 실행한다. 여러 개는 쉼표로 잇는다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check_requirements.ps1 -Skill neis-automation,alimjang-automation
```

줄마다 `[OK]`·`[없음]`·`[확인]` 중 하나다. 종료 코드 0은 빠진 것 없음, 1은 있음, 2는 잘못된 스킬 이름이다.

`[확인]`은 두 가지다. 일부 기능(급여명세서 CSV, 알림장 첨부 읽기·평일 자동 정리, 컴시간 자동 실행용 환경 변수)에만 필요한 항목은 사용자가 그 기능을 쓸 때만 설치를 안내한다. 스크립트가 판정할 수 없는 항목은 아래 절차로 마저 본다.

- **Playwright 브라우저 도구**(나이스·K-에듀파인·교데통·e알리미): 에이전트에 Playwright 도구(`browser_navigate` 등)가 있는지 본다. 없으면 "빠진 것"으로 보고하고, 에이전트 설정에 MCP 서버 `npx @playwright/mcp@latest`를 등록하도록 안내한다. 브라우저 제어 확장은 사용자가 쓰겠다고 할 때만 점검한다. 탭 목록은 되는데 클릭·캡처가 `Cannot attach to this target`이면 그 크롬에서 메뉴 ⋮ → 도구 더보기 → 개발자 도구를 열어 보게 하고, "조직에서 이 페이지의 DevTools 사용을 차단했습니다"가 뜨면 그 크롬에서는 확장을 쓸 수 없다고 알린다.
- **로그인된 크롬 이어 쓰기(선택, 업무포털 공통)**: 사용자가 이미 로그인해 둔 크롬에 에이전트를 붙이는 경로다(예: Chrome DevTools MCP의 `--autoConnect`, 크롬 144 이상). 스크립트가 PC의 크롬 정책을 읽고, 차단 정책이 없으면 임시 프로필로 크롬을 띄워 실제로 탭에 붙어 본 뒤 사용 가능·정책 차단·미확인(144 미만, 크롬 없음, 시험 실패)을 판정한다. 사용자에게 확인을 맡기지 않고 결과를 전한 뒤 다음 점검으로 넘어간다.
  - 사용 가능이고 사용자가 이 경로를 쓰겠다고 하면 평소 크롬에서 `chrome://inspect/#remote-debugging`을 열어 주거나 주소를 알려 준다. 원격 디버깅을 켜는 것만 사용자가 한다. 켜 두면 에이전트가 그 브라우저의 모든 탭과 로그인 세션에 접근할 수 있으니 업무를 마치면 끄라고 함께 알린다. 점검 단계에서는 켜지 않는다.
  - 시험은 PC 단위 정책만 반영한다. 크롬에 로그인한 계정에 걸린 정책이 연결을 막을 수 있으니, 실제 연결이 DevTools 차단으로 실패하면 Playwright로 돌아간다.
  - 기본 경로는 결과와 관계없이 Playwright다.
- **교육행정 전자서명 인증서**: 기본 위치에 없으면 이동식 매체나 다른 경로에 두었는지 사용자에게 묻는다. 인증서 암호는 묻지도 입력하지도 않는다.
- **알림장 첨부 읽기(권장)**: 기본 조회·검색·첨부 원본 저장과 분리해 보고한다. 한글 읽기 도구는 특정 스킬을 필수로 지정하지 않고 사용 가능한 도구를 확인한다. 예: `hwpx-tomd`는 HWPX 읽기 전용이고, `hwpx-automation`은 HWP 변환·HWPX 읽기를 지원한다. 이미 사용할 수 있는 도구가 있으면 추가 설치하지 않는다. 예약 자동화는 점검 결과의 연결 후보를 대표 첨부로 검증한 뒤 설정한다. 도구가 없거나 미검증이어도 기본 기능을 사용 불가로 판정하지 않는다. 설치·연결 방법은 [알림장 첨부 도구](../alimjang-automation/references/첨부-도구.md)를 본다.
- **알림장 서버 공유 폴더**: 학교 내부망에서 서버 PC가 켜져 있을 때만 보인다. 교외에서 점검했으면 교내에서 다시 확인하라고 안내한다.

접속 점검도 요청했을 때만 [접속 환경 확인](../neis-automation/SKILL.md#접속-환경-확인)을 따른다.
교육청 주소 등 개인 설정을 바꾸려는 경우에는 설치된 스킬 대신 로컬 프로젝트 지침에 적어 업데이트 때 보존한다.

## 3. 보고

알림장은 기본 기능 상태와 첨부 읽기의 형식별 연결·검증 상태를 구분한다. 스킬마다 한 줄로 "바로 사용 가능", "빠진 것: …", "설치 요건 충족, 접속 미확인" 중 확인한 상태를 적고, 빠진 것마다 스크립트가 낸 설치 방법을 붙인다. 업무포털 공통 항목(Playwright 도구·인증서 프로그램·인증서)이 빠졌으면 웹 세 스킬 모두에 해당한다고 한 번만 말한다. 로그인된 크롬 이어 쓰기는 스크립트 판정(사용 가능·정책 차단·미확인)을 업무포털 공통 줄에 덧붙이고, 빠진 것으로 세지 않는다. Playwright 도구가 없으면 e알리미도 쓸 수 없다. 설치는 사용자가 하겠다고 하면 그때 한다.
