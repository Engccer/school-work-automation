# 쿨메신저 자동화

교내 메신저 **쿨메신저(CoolMessenger Gentoo)**를 다룬다. 받은·보낸 메시지 조회와 받은 메시지의
첨부파일 내려받기가 기본 기능이고, 회신 정리와 회신·새 메시지 작성 창 채우기를 함께 다룬다.

> 쿨메시지 **문안 작성**은 이 스킬의 범위 밖이다. 이 스킬은 이미 주고받은 메시지의
> 조회와 회신 정리, 첨부 내려받기, 작성 창 채우기를 맡는다.

## 먼저 알아야 할 구조

쿨메신저는 **32비트 MFC 껍데기 + CEF(크롬) 뷰**다. 그래서 경로가 두 갈래다.

| 하고 싶은 일 | 방법 | 위험도 |
|---|---|---|
| 메시지·회신 내용 읽기 | 로컬 SQLite DB 직접 읽기 | 없음(읽기 전용) |
| 첨부파일 저장 | 창 조작(목록 클릭 → 저장 버튼) | 낮음 |
| 회신 작성 | 창 조작 + 클립보드 붙여넣기 | **발송은 사용자 확인 후** |
| 조직도·내선번호 가져오기 | 메인 창 조직도 트리를 펼쳐 읽기 | 없음(펼치기만, 발송 없음) |

**공식 자동화 API는 없다.** 첨부 저장과 회신 작성은 UI 자동화가 유일한 경로다. → 사례

### 실행 전제

`cm_export.py`는 `python`으로, `.ps1` 스크립트는 **`pwsh`(7)**로 실행한다
(`pwsh -NoProfile -ExecutionPolicy Bypass -File`).

**Windows PowerShell 5.1로는 돌리지 않는다.** 대상 프로세스 메모리를 읽는 함수(`Read-CMList`,
`Get-CMRowPoint`, `cm_tree.ps1` 전부)가 쓰는 `[UIntPtr]4096` 형변환이 5.1에서
`Cannot convert the "4096" value of type "System.Int32" to type "System.UIntPtr"`로 죽는다.
리터럴이어도 막히므로 우회할 방법이 없다(실측). → 사례

Windows PowerShell 5.1로 띄우는 임시 `.ps1`에 한글 경로나 문구가 있으면 **UTF-8 BOM으로 저장**한다.
파일 편집 도구가 만든 BOM 없는 UTF-8 스크립트는 ANSI로 읽혀 경로가 깨질 수 있다.
`[Console]::OutputEncoding`은 출력 설정일 뿐 스크립트 해독 오류를 고치지 않는다.
본문 `.txt`는 BOM 없이 저장해도 `Get-Content -Raw -Encoding UTF8`로 명시해 읽으면 된다.
현재 셸에서 라이브러리 로드가 출력 없이 종료되면 원인을 단정하지 말고 위의 `pwsh -File` 실행 경로로 재확인한다.

아래 명령은 모두 스킬 루트에서 실행한다.

## 1. 메시지 읽기 · DB 직접 읽기 (기본 경로)

메시지가 **암호화 없는 평문 SQLite**로 통째로 남는다.

```
%LOCALAPPDATA%\CoolMessenger\Memo\<사용자명>.udb    (+ -wal, -shm)
```

| 테이블 | 내용 |
|---|---|
| `tbl_recv` | 받은 메시지 · `Sender` `Title` `MessageText` `ReceiveDate` `FilePath` `IsUnRead` |
| `tbl_send` | 보낸 메시지 · `Receiver` `Title` `MessageText` `SendDate` `FilePath` |
| `tbl_member` | 조직 구성원 |

```bash
python scripts/cm_export.py --since 2026-09-21 --contains 체크리스트 --out 회신.csv
python scripts/cm_export.py --sent --since 2026-09-01 --format json
```

- `--contains`는 제목과 본문(인용문 포함)에서 찾는다. `--from`은 받은 메시지면 보낸사람,
  `--sent`면 받는사람을 거른다.
- 앱이 파일을 **잠그고 있으므로** 공유 읽기(`FileShare.ReadWrite`)로 복사한 뒤 연다.
  `File.ReadAllBytes`는 `다른 프로세스가 사용 중` 오류가 난다. `cm_export.py`는 이 사본을
  임시 폴더에 만들고 끝나면 지운다.
- **WAL 모드라 `-wal`·`-shm`까지 같이 복사**해야 방금 온 메시지가 보인다.
- 회신에는 원문이 `<보낸사람>님이 보낸글 >> <일시>`로 통째 인용돼 붙는다. 그 **줄의
  처음**에서 잘라야 이름이 남지 않는다(표시 위치에서 자르면 그 줄의 `<보낸사람>`이 본문 끝에 남는다).
- 첨부 정보는 `FilePath` 한 칸에 `|건수|크기;크기;|보낸사람쪽폴더|파일명|플래그|`로 들어 있고,
  첨부가 여러 개면 `폴더|파일명|플래그` 세 칸이 건수만큼 반복된다.
  폴더는 **보낸 사람 PC의 폴더**라 내 컴퓨터에는 그런 파일이 없다.
- **화면 목록보다 DB가 완전하다.** 관리함 목록에서 사라진 메시지도 DB에는 남는다.

### 회신만 골라내기

시간만으로 거르면 무관한 전체 공지가 섞인다. 두 조건을 같이 쓴다.

1. 본문에 인용 표시(`님이 보낸글`)가 있을 것 · 회신이라는 증거
2. 보낸사람이 대상자 명단에 있을 것

## 2. 받은 메시지 첨부파일 내려받기

회신이든 아니든 메시지 관리함의 받은 메시지라면 똑같이 내려받는다. 회신 첨부 수합은 그 대표 용례다.
대상은 첨부파일명 패턴 `-Match`로 고르고, `-From`을 주면 보낸사람 이름에 그 문구가 들어간 메시지만 남긴다(`-From`의 `*`·`[` 등은 글자 그대로 본다).
특정인이 보낸 첨부를 다 받으려면 `-Match '*' -From <이름>`이다. 파일명을 좁히고 싶으면 먼저
`cm_export.py --from <보낸사람> --since <날짜>`로 `첨부` 칸의 파일명을 확인한다.
`-Dest`에 같은 이름의 파일이 이미 있으면 `이미보관`으로 건너뛰므로, 같은 양식 파일을 여러 사람에게서 받을 때는
사람별 `-Dest`를 주고 `-From`으로 한 사람씩 받는다.
첨부가 여러 건인 메시지는 아래 「`그룹파일`」 절을 따르고, 관리함 목록 앞쪽 200행보다 오래된 메시지는 내보내기에는 보여도 받아지지 않는다.

```bash
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/cm_save_attachments.ps1 -Match '*체크리스트*' -Dest "$env:USERPROFILE\Documents\수합\체크리스트"
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/cm_save_attachments.ps1 -Match '*' -From 홍길동 -Dest "$env:USERPROFILE\Downloads\홍길동"
```

동작: 메시지 관리함 목록을 읽어 → 첨부파일명이 패턴과 맞는(그리고 `-From`에 맞는) 행을 **실제 마우스로 클릭** →
미리보기가 그 사람으로 바뀐 걸 확인 → `모든파일 저장` → 저장된 파일을 `-Dest`로 옮긴다.
목록은 앞쪽 200행만 읽는다(`cm_reply.ps1`은 60행). 그보다 오래된 메시지는 대상에 들지 않는다.

### 창을 착각하지 말 것: 수신 알림 창과 메시지 관리함

새 메시지가 오면 **수신 알림 창이 저절로 열린다.** 제목이 `N개의 안읽은 메시지`이고
목록·탭·버튼이 관리함과 똑같이 생겼지만, **방금 온 메시지 몇 건만** 담겨 있고 시간이
지나면 그마저 빠진다. 여기서 지난 첨부를 받으려 하면 목록에 그 메시지가 없다.

진짜 관리함은 제목이 정확히 `메시지 관리함`이고, 메인 창의 **[메시지관리함 열기](Ctrl+B)**
로 연다. 여기에는 받은 메시지가 전부 있고 **지난 첨부도 얼마든지 내려받을 수 있다.**
`Open-CMArchive`가 알림 창을 닫고 관리함을 열어 준다. 관리함은 늦게 뜰 때가 있어 제목을
최대 20초 폴링하고, 그래도 못 찾으면 오류를 낸다.

**첨부를 못 받으면 먼저 창부터 의심한다.** → 사례

### 첨부가 여러 개면 목록에 `그룹파일`로만 보인다

첨부가 2건 이상인 메시지는 목록 C3 칸이 파일명이 아니라 `그룹파일`이라 `cm_save_attachments.ps1 -Match`가
0건을 낸다. 이때는 `Select-CMMessage`로 행을 고른 뒤 미리보기의 `파일명 (NN KB)` 라벨로 첨부 목록을
확인하고 `모든파일 저장`을 누른다. 저장된 파일은 아래 저장 위치에서 파일명으로 찾아 옮긴다. → 사례

### 저장 위치는 고를 수 없다

`모든파일 저장`은 **대화상자 없이 바로 저장**한다. 저장 위치의 정본은 레지스트리
`HKCU\Software\Jiransoft\CoolMsg50\Option\GetFile` 키의 `DownPath` 값이다. 그래서 스크립트는
저장된 파일을 **파일명으로 찾아** `-Dest`로 옮긴다. `DownPath`를 먼저 보고, 폴백으로 기본 후보 폴더
(받은 파일 폴더·다운로드·바탕화면·`-Dest`와 그 상위)와 열린 탐색기 창의 폴더를 본 뒤, 마지막으로
사용자 프로필과 `-Dest` 드라이브 전체를 재귀로 찾는다. → 사례

`Documents` 아래 `&E94\`XV` 같은 이상한 폴더의 확장자별 동일 크기 파일은 랜섬웨어 방지 미끼 파일이니 무시한다.
`모든파일 다른폴더에 저장`도 있지만 폴더 선택 창이 뜬다.

### 다운로드가 멈추는 경우

**먼저 저장 폴더(`DownPath`)에 같은 이름 파일이 있는지 본다.** 있으면 쿨메신저가
`같은 이름을 가진 파일이 이미 존재합니다` 창([다시받기] [다른이름] [넘어가기] [받기취소])을
띄우고 전송이 거기서 멈춘다. 이 창은 제목이 달라 `파일 다운로드 중`만 찾으면 안 보이므로,
**전송멈춤으로 오진하기 쉽고 관리함에서 다시 시도해도 같은 창이 또 떠 영영 못 받는다.**
`-Dest` 충돌(`이미보관`)과는 다른 문제다. → 사례

`cm_save_attachments.ps1`이 저장을 누르기 전에 `DownPath`의 동명 파일을 검사해
`동명파일(저장폴더 …)`로 걸러 내고, `Wait-CMDownload`도 이 창을 만나면 [받기취소] 후
`DUPLICATE`를 돌려준다. 해결은 둘 중 하나다.

- **저장 폴더의 그 파일을 치우고 다시 받는다**(실측으로 통한 방법). `DownPath`가 업무 폴더로
  잡혀 있으면 작업 파일과 부딪히기 쉬우니 지우지 말고 옮긴다.
- `-Overwrite`를 준다. [다시받기]를 눌러 **저장 폴더의 기존 파일을 덮어쓴다**(미실측 경로).

그 다음이 진짜 전송 멈춤이다. `파일 다운로드 중` 창이 속도 0으로 멈춘 채 **오류 없이**
남아 있을 수 있다(실측 57분). `Wait-CMDownload`가 제한 시간 뒤 [취소]를 눌러 정리하고
`STALLED`를 돌려준다. 이때는 **관리함에서 다시 시도**하고, 그래도 안 되면 재전송을 요청한다.

### 목록 필터

목록 위 드롭다운이 `안읽은 메시지`로 되어 있으면 읽은 것은 안 보인다. `전체 메시지`로
바꾼다 · 드롭다운은 커스텀 팝업(`CMenuEx`)이라 버튼을 클릭해 연 뒤 항목을 다시 클릭해야
하고, 고르고 나면 팝업 창이 남으므로 `WM_CLOSE`로 닫는다.

## 3. 회신·새 메시지 작성 · 발송 동의 범위에서 처리

사용자가 수신자·본문을 지정해 "발송해 줘"라고 요청했다면 발송에 동의한 것이다.
받는사람과 본문을 검증한 뒤 발송하고 DB로 확인한다. 초안·작성만 요청했다면 채우기까지만 한다.

### 조직도에서 한 사람에게 새 메시지 작성 · `cm_send_new.ps1`

같은 안내문을 여러 사람에게 **개별 발송**할 때(한 통씩 따로, 각자 다른 첨부) 이 경로를 쓴다.
받는사람이 한 명뿐이라 오발송 위험이 가장 낮다.

```bash
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/cm_send_new.ps1 `
     -Name 홍길동 -TitleFile 제목.txt -BodyFile 본문.txt -Attach '.\양식.hwp' -Shot shot.png [-Send]
```

사람 수만큼 돌린다. `-Send` 없이 부르면 채우기까지만 하고 캡처를 남긴다.
스크립트가 하는 일과 그 근거는 다음과 같다.

- 조직도는 메인 창의 `SysTreeView32`(`GetWindowText`가 `조직도`)다. `cm_tree.ps1`이 트리를 펼치며
  항목을 모으고, 이름이 **두 개 이상의 계정 글자**에 걸리면 동명이인이므로 멈춘다.
- **한 사람이 조직도 여러 곳에 중복해 나온다**(부서별). 계정 글자가 같으면 아무 곳이나 써도 된다.
- 화면 밖 항목은 좌표가 음수로 나오므로 `TVM_ENSUREVISIBLE` **뒤에 좌표를 다시 읽는다.**
  클릭 직전 `WindowFromPoint`로 그 좌표가 트리 위인지 확인한다.
- 더블클릭은 커서를 둔 뒤 `mouse_event` down/up 쌍을 **80ms 간격으로 두 번**(실측 성공).
  `Invoke-CMClick`은 내부 대기가 있어 두 번 연속 불러도 더블클릭이 되지 않고,
  단순 선택 뒤 Enter도 작성 창을 열지 못했다.
- **작성 창은 손대지 않으면 저절로 닫힌다**(실측). 그래서 열기·제목·본문·첨부를 **한 번의 실행**에서
  끝내야 한다. 열어 두고 다음 호출에서 채우려 하면 창이 이미 없다.
- 받는사람 라벨은 학생이면 `이름(학년-반) 번호 담당(이름)`, 교직원이면 `이름 계정번호 담당(이름)` 꼴이다
  (예: `홍길동 101 기획(홍길동)`). 스크립트가 **한 명인지, 그 사람인지** 확인하고 아니면 발송하지 않는다.
- 제목은 `Edit` **id=4362**. 클립보드로 붙인 뒤 `GetWindowText`로 읽으면 **빈 문자열**이지만
  실제로는 들어가 있다(캡처와 `tbl_send.Title`로 확인). 비었다고 다시 넣지 않는다.
- 첨부가 붙으면 창 하단에 `파일명 (NN KB)` 라벨이 생긴다. 스크립트는 파일명으로 대조한다.
- 검색란 붙여넣기가 화면에 반영되지 않으면 검색 성공으로 간주하지 말고 조직도를 이용한다.

### 받은 메시지에 회신 작성

`메시지 회신 (Ctrl+R)` → `메시지 전송 (크롬에디터)` 창이 뜬다. 받는사람은 자동으로 채워진다.

- `보내기`·`파일첨부`·`닫기`는 네이티브 버튼이라 제어된다.
- 본문은 **CEF 에디터**다. 한글 타이핑은 깨질 수 있으니 **클립보드 붙여넣기**를 쓴다
  (UTF-8 파일로 저장 → `Get-Content -Encoding UTF8 | Set-Clipboard` → Ctrl+V).
- **붙여넣기는 캐럿 위치에 들어간다.** 그냥 붙이면 인용문 한가운데에 박힌다.
  먼저 Ctrl+Home으로 본문 맨 앞에 커서를 두고 붙인다.
- 창을 닫으면 `이 창을 닫으시겠습니까?` 확인이 뜬다.

**`보내기`는 사용자가 발송에 동의했을 때만 누른다.** 그 전에는 채우기까지만 하고
`PrintWindow`로 캡처해 **받는사람과 본문을 눈으로 확인**한다. 교내 메신저는 한 번
나가면 회수가 번거롭고 수신자가 바로 읽는다.

### 여러 명에게 새 메시지 보내기 · 보낸 메시지의 [전체 회신]으로 받는사람을 재사용

조직도에서 여러 명을 고르는 대신, 같은 대상에게 보냈던 메시지를 관리함 **[보낸메시지]** 탭에서
클릭하고 **[전체 회신 (Ctrl+Shift+R)]**을 누르면 받는사람이 통째로 채워진 작성 창이 뜬다
(보낸메시지 탭에는 `전체 회신`·`재전송`·`전달`이 있다). 여기서 빼야 할 사람만 지운다. → 사례

- 받는사람은 이름 라벨 + 바로 뒤 형제 `Button 'delete'`(id 8010, **모두 같은 id**라 `WM_COMMAND` 불가) 쌍이다. 그 hwnd에 `BM_CLICK`.
- **받는사람 칸이 스크롤돼 안 보이는(`IsWindowVisible` false) 항목은 `BM_CLICK`이 무시된다.** 보이는 것부터 지우면 뒤 항목이 올라오니, 보이는 것만 누르는 루프를 여러 번 돌린다.
- 원 메시지에 **참조로 넣었던 사람(예: 부장)도 받는사람에 섞여** 들어온다.
- 본문은 CEF를 클릭 → Ctrl+A → Ctrl+V로 인용문째 교체. 제목(`Edit`)은 클릭 → Ctrl+A → 붙여넣기(회색으로 보여도 실제로 들어간다, `tbl_send.Title`로 확인).
- 첨부: [파일첨부]를 `PostMessage BM_CLICK`(모달이라 `SendMessage` 금지) → "열기" 창 `Edit id=1148`에 따옴표 경로 `WM_SETTEXT` → `WM_COMMAND 1`. 작성 창 하단에 `파일명 (NN KB)` 라벨이 생기면 성공.
- 받는사람 수를 셀 때 **첨부 라벨도 `이름(…)` 패턴 + `delete` 형제를 가져 받는사람으로 오인**된다. 확장자로 제외한다.

### 발송 확인은 창이 닫힌 것으로 판단하지 않는다

`보내기`의 `BM_CLICK`은 **15초를 넘겨 늦게 반영될 수도 있다.** 창이 안 닫혔다고 다시
누르면 중복 발송이 되고, 반대로 창이 닫혔다고 발송을 단정해도 안 된다.
`cm_reply.ps1 -Send`도 4초 뒤 창이 닫혔는지만 알려 주고 `tbl_send` 확인을 안내한다.
`회신 창이 아직 열려 있습니다`가 떠도 다시 누르지 않는다.
**`tbl_send`를 조회해 실제로 들어갔는지 확인한다.**

첫 DB 조회가 0건이어도 미발송 증거로 삼아 다시 누르지 않는다. 발송 클릭 이후에는 UI 재시도를 멈추고
새 DB 사본(WAL 포함)으로 수신자·본문·시각을 몇 초 간격으로 재조회한다. 60초 동안 확인되지 않으면
상태 미확인으로 보고하고 자동 재발송하지 않는다(60초는 운영상 조회 제한이며 서버 지연의 상한이 아니다).
클릭 후 작성 창이 사라져 활성화가 실패한 경우에도 먼저 DB를 확인한다.
구체적 실측 경위는 [references/cases.md](references/cases.md)의 「발송 확인」을 참고한다.

```bash
python scripts/cm_export.py --sent --since "2026-09-22 12:00" --out sent.csv
```

### 광고 팝업이 클릭을 가로챈다

쿨메신저는 수시로 광고 창(`한가위에도…` 등)을 띄우는데, 이게 맨 앞에 오면
실제 마우스 클릭도 `BM_CLICK`도 먹지 않는다. **조작 전에 최상위 창 목록을 확인**하고
낯선 제목의 `#32770`이 있으면 `WM_CLOSE`로 닫는다.

### 회신은 여러 번 나뉘어 온다

"6번 빠뜨렸네요" 같은 추가 회신이 흔하다. 한 사람의 **최신 메시지만 취하면 앞서 받은
답변이 통째로 사라진다**. → 사례
같은 사람의 회신을 시간순으로 모아 **빈칸을 채우는 방향으로 병합**한다.

번호 표기도 제각각이라 `3.예`(공백 없음), `6번 전체 인원 수`(구분자 대신 '번'),
`전체인원 수`(띄어쓰기 다름)를 모두 받아야 한다. 다만 번호 뒤에 아무 표시가 없으면
`2026년` 같은 숫자를 문항으로 오인하므로 `[.,)]`나 '번'은 반드시 요구한다.

## 4. 조직도 내보내기 · 소속·내선번호 포함 CSV

조직도 트리 항목 글자에는 `(이름(학년-반) 내선 담당)꼬리` 꼴로 내선번호와 담당이 들어 있다.
트리를 펼쳐 소속 경로와 함께 CSV(UTF-8 BOM)로 뽑는다. 노드를 열 뿐 메시지를 보내거나 바꾸지 않는다.

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/cm_org_chart.ps1 -Out <임시폴더>\org_tree.tsv [-Launch]
```

```bash
python scripts/cm_org_csv.py <임시폴더>/org_tree.tsv --out "<저장 폴더>/조직도 (YYYY-MM-DD 요일).csv" --check-db
```

1. **쿨메신저를 켠다.** 꺼져 있으면 `-Launch`가 기본 설치 경로의 `CoolMessenger.exe`를 띄우고 조직도가
   뜰 때까지 최대 40초 기다린다. 로그인 창이 떠 있으면 사용자가 직접 로그인한 뒤 다시 실행한다.
   켜지면서 뜨는 `N개의 안읽은 메시지` 알림 창은 무시한다. → 사례
2. `cm_org_chart.ps1`이 TSV를 쓴다. 행은 `상위 경로<TAB>항목 글자`이고 그룹 노드도 행으로 나온다.
3. `cm_org_csv.py`가 사람 행만 골라 CSV를 쓴다. 열은 이름, 학년-반, 내선번호, 담당, 소속(조직도 경로),
   상태 메시지다. 여러 그룹에 나온 사람은 소속을 ` / `로 모으고 그룹 아래 그룹은 ` > `로 잇는다.
4. TSV는 임시 파일이다. CSV를 저장하고 나면 지운다.

이 절차의 근거와 함정(실측):

- **트리는 깊이 우선으로 펼쳐야 소속이 맞는다.** `TVGN_CHILD`·`TVGN_NEXT`를 한 줄로 돌리며 자식을
  나중에 훑으면 깊이 값은 맞아도 순서가 섞여 어느 그룹 아래인지 잃는다. `cm_org_chart.ps1`은 항목마다
  자식으로 바로 내려가고, 행의 경로는 그 재귀로 만든다. → 사례
- 조직도 최상위는 학교 이름 하나이고, 그 아래에 부서·담임·교과 같은 그룹이 있다. **같은 사람이 여러 그룹에
  중복해 나오므로** 이름 기준으로 모은다.
- 항목 글자 해석:
  - 바깥 괄호 안이 사람이고, 괄호 밖 글자는 상태 메시지다. 괄호는 **깊이로 짝을 맞춘다**(학년-반 괄호가 안에 있다).
  - `이름(학년-반) 내선 담당` 순이다. 내선은 2~4자리 숫자이고 **숫자 뒤에 숫자가 이어지지 않는 것**으로 본다.
    `\b`로 경계를 잡으면 내선 바로 뒤에 한글이 붙은 항목(`내선한글담당`)을 내선으로 못 알아봐 담당에 숫자가 섞인다(실측).
  - 내선 없이 `이름 (담당)`만 있는 사람이 있다. 빈 칸으로 둔다.
  - 꼬리가 내선 숫자를 그대로 반복한 것은 중복 표시이므로 비운다. 그 밖의 꼬리는 개인 상태 문구(부재 안내 등)일
    수 있으니 CSV를 공유하기 전에 확인한다.
  - 한글 이름으로 시작하지 않는 항목(계정만 있는 것)은 사람이 아니므로 뺀다.
  - 같은 사람의 내선·담당이 그룹마다 다르면 빈 칸만 채우고 경고를 낸다.
- `--check-db`는 쿨메신저 DB의 `tbl_member`를 **사본으로** 읽어 이름별 내선·담당을 대조한다. 명단
  `MemberName`은 `이름 내선 담당` 꼴(괄호 없음)이다. 명단에는 조직도에서 빠진 과거 구성원이 섞여 있어
  CSV에는 넣지 않고 "명단에만 있음"으로만 알린다. 앱을 켤 수 없을 때 명단만으로 내선 목록을 임시로 만들
  수는 있으나 소속이 없고 과거 구성원이 섞이니 임시용으로만 쓴다.
- 결과 CSV에는 교직원 연락처가 들어 있다. 업무 폴더에만 두고 외부에 보내지 않는다.

시험: `python -m unittest discover -s scripts/tests`(가짜 이름·가짜 TSV·가짜 DB만 쓴다).

## 5. 창 조작의 함정 (전부 실측)

### 포그라운드 잠금 · ALT 트릭이 필요하다

`SetForegroundWindow`는 그냥은 **조용히 실패**한다(`True`를 반환해도 활성화 안 됨).
그러면 실제 마우스 클릭이 **화면 맨 앞의 엉뚱한 창(크롬 등)으로 간다.**
`SetWindowPos`에 `HWND_TOPMOST`를 줘도 `WS_EX_TOPMOST`가 안 붙어 소용없었다.

통하는 방법은 **ALT를 눌렀다 떼면서 `SetForegroundWindow`를 호출**하는 것이다
(시스템이 사용자 조작으로 간주). `Set-CMActive`가 이것을 하고 성공 여부를 돌려준다.

### 목록 선택은 반드시 **실제 클릭**으로

`LVM_SETITEMSTATE`로 선택 상태를 바꾸면 **선택 표시는 옮겨가지만 미리보기는 그대로**다
(`LVM_GETNEXTITEM`으로 확인하면 분명히 바뀌어 있는데도). 키보드 `VK_UP`/`VK_RETURN`
전송도 마찬가지다. 이 상태로 `모든파일 저장`을 누르면 **엉뚱한 사람의 첨부가 저장된다.**

→ `Select-CMMessage`는 클릭 후 **`보낸사람 :` 헤더가 기대한 사람인지 확인**하고 재시도한다.

### 32비트 대상의 구조체

목록 항목을 읽으려면 `LVITEMW`를 대상 프로세스 메모리에 써야 하는데, 쿨메신저는
**32비트**라 포인터가 4바이트다. 64비트 레이아웃을 쓰면 엉뚱한 값을 읽는다.
`pszText`는 오프셋 20, `cchTextMax`는 24다.

### 버튼 클릭 방식이 창마다 다르다

| 대상 | 통하는 방법 |
|---|---|
| 메인·관리함·작성 창의 버튼(`메시지관리함 열기`·`모든파일 저장`·`메시지 회신`·`보내기`) | `BM_CLICK`(0x00F5) · 단 창이 활성 상태여야 할 때가 있다 |
| 모달 대화상자의 버튼(`파일 다운로드 중`의 [취소], 첨부 "열기" 창의 [열기]) | `WM_COMMAND` + **컨트롤 ID** (`파일 다운로드 중`에서는 `BM_CLICK`이 무시됐다) |
| 그 밖의 창 | `BM_CLICK`을 보내고 창에 변화가 없으면 `WM_COMMAND` + 컨트롤 ID |
| 커스텀 팝업(`CMenuEx`) 항목 | 실제 마우스 클릭 |

대화상자 컨트롤 ID는 **창마다 다르다**(확인=1, 2, 5025 등). `GetDlgCtrlID`로 매번 읽는다.

### `SendMessage`는 절대 쓰지 말 것

앱이 모달을 띄우면 영영 돌아오지 않는다. 항상 `SendMessageTimeout`(라이브러리의 `[CM]::Msg`)
또는 `PostMessage`를 쓴다.

### 가려진 창 캡처

`CopyFromScreen`은 맨 앞 창을 찍으므로 엉뚱한 화면이 나온다. `PrintWindow`에
`PW_RENDERFULLCONTENT`(플래그 2)를 주면 **가려져 있어도** 제대로 찍힌다.

### 한글 출력은 파일로

파이썬·파워셸 출력을 터미널로 흘리면 한글이 깨져 **실패로 오판**하기 쉽다.
UTF-8 파일로 써서 읽는다. CSV는 `utf-8-sig`(BOM)로 저장해야 엑셀에서 바로 열린다.

## 6. 작업 후 반드시 확인할 것

창 조작은 흔적을 남긴다. 끝내기 전에 **남은 창이 없는지 확인**한다.

```powershell
. .\scripts\cm_lib.ps1
foreach ($t in [CM]::Tops([uint32](Get-CMPid))) {
  if ([CM]::IsWindowVisible($t)) { "[$([CM]::Cls($t))] '$([CM]::Txt($t))'" }
}
```

정상 상태는 `COOLMESSENGER`(메인) + `N개의 안읽은 메시지`(수신 알림 창, 관리함 아님) 정도다.
`파일 다운로드 중`, `메시지 전송 (크롬에디터)`, `CMenuEx`가 남아 있으면 정리한다.
창 닫기는 `[void][CM]::PostMessage($h, 0x0010, [IntPtr]::Zero, [IntPtr]::Zero)`다(`[CM]::Post`는 없다).
클립보드를 테스트로 덮어썼다면 되돌려 놓는다.
