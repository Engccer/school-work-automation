# 쿨메신저 자동화

교내 메신저 **쿨메신저(CoolMessenger Gentoo)**를 다룬다. 안내 쿨메시지를 보낸 뒤
회신을 수합하는 업무(교육청 프로그램 회신 수합, 교과협의, 각종 제출 독촉)가 주 용도다.

> 쿨메시지 **문안 작성**은 이 스킬의 범위 밖이다. 이 스킬은 발송 이후의
> 회신 확인·첨부 수집·집계를 맡는다.

## 먼저 알아야 할 구조

쿨메신저는 **32비트 MFC 껍데기 + CEF(크롬) 뷰**다. 그래서 경로가 두 갈래다.

| 하고 싶은 일 | 방법 | 위험도 |
|---|---|---|
| 메시지·회신 내용 읽기 | 로컬 SQLite DB 직접 읽기 | 없음(읽기 전용) |
| 첨부파일 저장 | 창 조작(목록 클릭 → 저장 버튼) | 낮음 |
| 회신 작성 | 창 조작 + 클립보드 붙여넣기 | **발송은 사용자 확인 후** |

**공식 자동화 API는 없다.** 첨부 저장과 회신 작성은 UI 자동화가 유일한 경로다. → 사례

### 실행 전제

`cm_export.py`는 `python`으로, `.ps1` 스크립트는 **`pwsh`(PowerShell 7)**로 실행한다.
`cm_lib.ps1`은 BOM 없는 UTF-8이라 `powershell.exe`(5.1)로 점 소싱하면 한글 경로·문자열이
ANSI로 읽혀 구문 오류가 난다. → 사례

아래 명령은 모두 스킬 루트에서 실행한다.

## 1. 메시지 읽기 — DB 직접 읽기 (기본 경로)

메시지가 **암호화 없는 평문 SQLite**로 통째로 남는다.

```
%LOCALAPPDATA%\CoolMessenger\Memo\<사용자명>.udb    (+ -wal, -shm)
```

| 테이블 | 내용 |
|---|---|
| `tbl_recv` | 받은 메시지 — `Sender` `Title` `MessageText` `ReceiveDate` `FilePath` `IsUnRead` |
| `tbl_send` | 보낸 메시지 — `Receiver` `Title` `MessageText` `SendDate` `FilePath` |
| `tbl_member` | 조직 구성원 |

```bash
python scripts/cm_export.py --since 2026-09-21 --contains 체크리스트 --out 회신.csv
python scripts/cm_export.py --sent --since 2026-09-01 --format json
```

- `--contains`는 제목과 본문(인용문 포함)에서 찾는다. `--from`은 받은 메시지면 보낸사람,
  `--sent`면 받는사람을 거른다.
- 앱이 파일을 **잠그고 있으므로** 공유 읽기(`FileShare.ReadWrite`)로 복사한 뒤 연다.
  `File.ReadAllBytes`는 `다른 프로세스가 사용 중` 오류가 난다. `cm_export.py`는 이 사본을
  임시 폴더에 만들고 끝나면 지운다.
- **WAL 모드라 `-wal`·`-shm`까지 같이 복사**해야 방금 온 메시지가 보인다.
- 회신에는 원문이 `<보낸사람>님이 보낸글 >> <일시>`로 통째 인용돼 붙는다. 그 **줄의
  처음**에서 잘라야 이름이 남지 않는다(표시 위치에서 자르면 그 줄의 `<보낸사람>`이 본문 끝에 남는다).
- 첨부 정보는 `FilePath` 한 칸에 `|건수|크기;크기;|보낸사람쪽폴더|파일명|플래그|`로 들어 있고,
  첨부가 여러 개면 `폴더|파일명|플래그` 세 칸이 건수만큼 반복된다.
  폴더는 **보낸 사람 PC의 폴더**라 내 컴퓨터에는 그런 파일이 없다.
- **화면 목록보다 DB가 완전하다.** 관리함 목록에서 사라진 메시지도 DB에는 남는다.

### 회신만 골라내기

시간만으로 거르면 무관한 전체 공지가 섞인다. 두 조건을 같이 쓴다.

1. 본문에 인용 표시(`님이 보낸글`)가 있을 것 — 회신이라는 증거
2. 보낸사람이 대상자 명단에 있을 것

## 2. 첨부파일 일괄 수집

```bash
pwsh -File scripts/cm_save_attachments.ps1 -Match '*체크리스트*' -Dest "$env:USERPROFILE\Documents\수합\체크리스트"
```

동작: 메시지 관리함 목록을 읽어 → 첨부파일명이 패턴과 맞는 행을 **실제 마우스로 클릭** →
미리보기가 그 사람으로 바뀐 걸 확인 → `모든파일 저장` → 저장된 파일을 `-Dest`로 옮긴다.
목록은 앞쪽 200행만 읽는다(`cm_reply.ps1`은 60행). 그보다 오래된 메시지는 대상에 들지 않는다.

### 창을 착각하지 말 것: 수신 알림 창과 메시지 관리함

새 메시지가 오면 **수신 알림 창이 저절로 열린다.** 제목이 `N개의 안읽은 메시지`이고
목록·탭·버튼이 관리함과 똑같이 생겼지만, **방금 온 메시지 몇 건만** 담겨 있고 시간이
지나면 그마저 빠진다. 여기서 지난 첨부를 받으려 하면 목록에 그 메시지가 없다.

진짜 관리함은 제목이 정확히 `메시지 관리함`이고, 메인 창의 **[메시지관리함 열기](Ctrl+B)**
로 연다. 여기에는 받은 메시지가 전부 있고 **지난 첨부도 얼마든지 내려받을 수 있다.**
`Open-CMArchive`가 알림 창을 닫고 관리함을 열어 준다. 관리함은 늦게 뜰 때가 있어 제목을
최대 20초 폴링하고, 그래도 못 찾으면 오류를 낸다.

**첨부를 못 받으면 먼저 창부터 의심한다.** → 사례

### 첨부가 여러 개면 목록에 `그룹파일`로만 보인다

첨부가 2건 이상인 메시지는 목록 C3 칸이 파일명이 아니라 `그룹파일`이라 `cm_save_attachments.ps1 -Match`가
0건을 낸다. 이때는 `Select-CMMessage`로 행을 고른 뒤 미리보기의 `파일명 (NN KB)` 라벨로 첨부 목록을
확인하고 `모든파일 저장`을 누른다. 저장된 파일은 아래 저장 위치에서 파일명으로 찾아 옮긴다. → 사례

### 저장 위치는 고를 수 없다

`모든파일 저장`은 **대화상자 없이 바로 저장**한다. 저장 위치의 정본은 레지스트리
`HKCU\Software\Jiransoft\CoolMsg50\Option\GetFile` 키의 `DownPath` 값이다. 그래서 스크립트는
저장된 파일을 **파일명으로 찾아** `-Dest`로 옮긴다. `DownPath`를 먼저 보고, 폴백으로 기본 후보 폴더
(받은 파일 폴더·다운로드·바탕화면·`-Dest`와 그 상위)와 열린 탐색기 창의 폴더를 본 뒤, 마지막으로
사용자 프로필과 `-Dest` 드라이브 전체를 재귀로 찾는다. → 사례

`Documents` 아래 `&E94\`XV` 같은 이상한 폴더의 확장자별 동일 크기 파일은 랜섬웨어 방지 미끼 파일이니 무시한다.
`모든파일 다른폴더에 저장`도 있지만 폴더 선택 창이 뜬다.

### 다운로드가 멈추는 경우

`파일 다운로드 중` 창이 속도 0으로 멈춘 채 **오류 없이** 남아 있을 수 있다(실측 57분).
`Wait-CMDownload`가 제한 시간 뒤 [취소]를 눌러 정리하고 `STALLED`를 돌려준다.
이때는 **관리함에서 다시 시도**하고, 그래도 안 되면 재전송을 요청한다.

### 목록 필터

목록 위 드롭다운이 `안읽은 메시지`로 되어 있으면 읽은 것은 안 보인다. `전체 메시지`로
바꾼다 — 드롭다운은 커스텀 팝업(`CMenuEx`)이라 버튼을 클릭해 연 뒤 항목을 다시 클릭해야
하고, 고르고 나면 팝업 창이 남으므로 `WM_CLOSE`로 닫는다.

## 3. 회신 작성 — 채우기까지만, 발송은 사용자

`메시지 회신 (Ctrl+R)` → `메시지 전송 (크롬에디터)` 창이 뜬다. 받는사람은 자동으로 채워진다.

- `보내기`·`파일첨부`·`닫기`는 네이티브 버튼이라 제어된다.
- 본문은 **CEF 에디터**다. 한글 타이핑은 깨질 수 있으니 **클립보드 붙여넣기**를 쓴다
  (UTF-8 파일로 저장 → `Get-Content -Encoding UTF8 | Set-Clipboard` → Ctrl+V).
- **붙여넣기는 캐럿 위치에 들어간다.** 그냥 붙이면 인용문 한가운데에 박힌다.
  먼저 Ctrl+Home으로 본문 맨 앞에 커서를 두고 붙인다.
- 창을 닫으면 `이 창을 닫으시겠습니까?` 확인이 뜬다.

**`보내기`는 사용자가 발송에 동의했을 때만 누른다.** 그 전에는 채우기까지만 하고
`PrintWindow`로 캡처해 **받는사람과 본문을 눈으로 확인**한다. 교내 메신저는 한 번
나가면 회수가 번거롭고 수신자가 바로 읽는다.

### 여러 명에게 새 메시지 보내기 — 보낸 메시지의 [전체 회신]으로 받는사람을 재사용

조직도에서 여러 명을 고르는 대신, 같은 대상에게 보냈던 메시지를 관리함 **[보낸메시지]** 탭에서
클릭하고 **[전체 회신 (Ctrl+Shift+R)]**을 누르면 받는사람이 통째로 채워진 작성 창이 뜬다
(보낸메시지 탭에는 `전체 회신`·`재전송`·`전달`이 있다). 여기서 빼야 할 사람만 지운다. → 사례

- 받는사람은 이름 라벨 + 바로 뒤 형제 `Button 'delete'`(id 8010, **모두 같은 id**라 `WM_COMMAND` 불가) 쌍이다. 그 hwnd에 `BM_CLICK`.
- **받는사람 칸이 스크롤돼 안 보이는(`IsWindowVisible` false) 항목은 `BM_CLICK`이 무시된다.** 보이는 것부터 지우면 뒤 항목이 올라오니, 보이는 것만 누르는 루프를 여러 번 돌린다.
- 원 메시지에 **참조로 넣었던 사람(예: 부장)도 받는사람에 섞여** 들어온다.
- 본문은 CEF를 클릭 → Ctrl+A → Ctrl+V로 인용문째 교체. 제목(`Edit`)은 클릭 → Ctrl+A → 붙여넣기(회색으로 보여도 실제로 들어간다, `tbl_send.Title`로 확인).
- 첨부: [파일첨부]를 `PostMessage BM_CLICK`(모달이라 `SendMessage` 금지) → "열기" 창 `Edit id=1148`에 따옴표 경로 `WM_SETTEXT` → `WM_COMMAND 1`. 작성 창 하단에 `파일명 (NN KB)` 라벨이 생기면 성공.
- 받는사람 수를 셀 때 **첨부 라벨도 `이름(…)` 패턴 + `delete` 형제를 가져 받는사람으로 오인**된다. 확장자로 제외한다.

### 발송 확인은 창이 닫힌 것으로 판단하지 않는다

`보내기`의 `BM_CLICK`은 **5~15초 늦게 반영될 때가 있다.** 창이 안 닫혔다고 다시
누르면 중복 발송이 되고, 반대로 창이 닫혔다고 발송을 단정해도 안 된다.
`cm_reply.ps1 -Send`도 4초 뒤 창이 닫혔는지만 알려 주고 `tbl_send` 확인을 안내한다.
`회신 창이 아직 열려 있습니다`가 떠도 다시 누르지 않는다.
**`tbl_send`를 조회해 실제로 들어갔는지 확인한다.**

```bash
python scripts/cm_export.py --sent --since "2026-09-22 12:00" --out sent.csv
```

### 광고 팝업이 클릭을 가로챈다

쿨메신저는 수시로 광고 창(`한가위에도…` 등)을 띄우는데, 이게 맨 앞에 오면
실제 마우스 클릭도 `BM_CLICK`도 먹지 않는다. **조작 전에 최상위 창 목록을 확인**하고
낯선 제목의 `#32770`이 있으면 `WM_CLOSE`로 닫는다.

### 회신은 여러 번 나뉘어 온다

"6번 빠뜨렸네요" 같은 추가 회신이 흔하다. 한 사람의 **최신 메시지만 취하면 앞서 받은
답변이 통째로 사라진다**. → 사례
같은 사람의 회신을 시간순으로 모아 **빈칸을 채우는 방향으로 병합**한다.

번호 표기도 제각각이라 `3.예`(공백 없음), `6번 전체 인원 수`(구분자 대신 '번'),
`전체인원 수`(띄어쓰기 다름)를 모두 받아야 한다. 다만 번호 뒤에 아무 표시가 없으면
`2026년` 같은 숫자를 문항으로 오인하므로 `[.,)]`나 '번'은 반드시 요구한다.

## 4. 창 조작의 함정 (전부 실측)

### 포그라운드 잠금 — ALT 트릭이 필요하다

`SetForegroundWindow`는 그냥은 **조용히 실패**한다(`True`를 반환해도 활성화 안 됨).
그러면 실제 마우스 클릭이 **화면 맨 앞의 엉뚱한 창(크롬 등)으로 간다.**
`SetWindowPos`에 `HWND_TOPMOST`를 줘도 `WS_EX_TOPMOST`가 안 붙어 소용없었다.

통하는 방법은 **ALT를 눌렀다 떼면서 `SetForegroundWindow`를 호출**하는 것이다
(시스템이 사용자 조작으로 간주). `Set-CMActive`가 이것을 하고 성공 여부를 돌려준다.

### 목록 선택은 반드시 **실제 클릭**으로

`LVM_SETITEMSTATE`로 선택 상태를 바꾸면 **선택 표시는 옮겨가지만 미리보기는 그대로**다
(`LVM_GETNEXTITEM`으로 확인하면 분명히 바뀌어 있는데도). 키보드 `VK_UP`/`VK_RETURN`
전송도 마찬가지다. 이 상태로 `모든파일 저장`을 누르면 **엉뚱한 사람의 첨부가 저장된다.**

→ `Select-CMMessage`는 클릭 후 **`보낸사람 :` 헤더가 기대한 사람인지 확인**하고 재시도한다.

### 32비트 대상의 구조체

목록 항목을 읽으려면 `LVITEMW`를 대상 프로세스 메모리에 써야 하는데, 쿨메신저는
**32비트**라 포인터가 4바이트다. 64비트 레이아웃을 쓰면 엉뚱한 값을 읽는다.
`pszText`는 오프셋 20, `cchTextMax`는 24다.

### 버튼 클릭 방식이 창마다 다르다

| 대상 | 통하는 방법 |
|---|---|
| 메인·관리함·작성 창의 버튼(`메시지관리함 열기`·`모든파일 저장`·`메시지 회신`·`보내기`) | `BM_CLICK`(0x00F5) — 단 창이 활성 상태여야 할 때가 있다 |
| 모달 대화상자의 버튼(`파일 다운로드 중`의 [취소], 첨부 "열기" 창의 [열기]) | `WM_COMMAND` + **컨트롤 ID** (`파일 다운로드 중`에서는 `BM_CLICK`이 무시됐다) |
| 그 밖의 창 | `BM_CLICK`을 보내고 창에 변화가 없으면 `WM_COMMAND` + 컨트롤 ID |
| 커스텀 팝업(`CMenuEx`) 항목 | 실제 마우스 클릭 |

대화상자 컨트롤 ID는 **창마다 다르다**(확인=1, 2, 5025 등). `GetDlgCtrlID`로 매번 읽는다.

### `SendMessage`는 절대 쓰지 말 것

앱이 모달을 띄우면 영영 돌아오지 않는다. 항상 `SendMessageTimeout`(라이브러리의 `[CM]::Msg`)
또는 `PostMessage`를 쓴다.

### 가려진 창 캡처

`CopyFromScreen`은 맨 앞 창을 찍으므로 엉뚱한 화면이 나온다. `PrintWindow`에
`PW_RENDERFULLCONTENT`(플래그 2)를 주면 **가려져 있어도** 제대로 찍힌다.

### 한글 출력은 파일로

파이썬·파워셸 출력을 터미널로 흘리면 한글이 깨져 **실패로 오판**하기 쉽다.
UTF-8 파일로 써서 읽는다. CSV는 `utf-8-sig`(BOM)로 저장해야 엑셀에서 바로 열린다.

## 5. 작업 후 반드시 확인할 것

창 조작은 흔적을 남긴다. 끝내기 전에 **남은 창이 없는지 확인**한다(`pwsh`에서).

```powershell
. .\scripts\cm_lib.ps1
foreach ($t in [CM]::Tops([uint32](Get-CMPid))) {
  if ([CM]::IsWindowVisible($t)) { "[$([CM]::Cls($t))] '$([CM]::Txt($t))'" }
}
```

정상 상태는 `COOLMESSENGER`(메인) + `N개의 안읽은 메시지`(수신 알림 창, 관리함 아님) 정도다.
`파일 다운로드 중`, `메시지 전송 (크롬에디터)`, `CMenuEx`가 남아 있으면 정리한다.
클립보드를 테스트로 덮어썼다면 되돌려 놓는다.
